# check — 提交前检查

当用户说"跑一遍 check"、"提交前检查"、"检查代码"、"pre-commit check"时执行。

## 流程

### 1. 看清改了什么

- `git status --short`
- `git diff --stat HEAD`

若无任何改动，告知用户并结束。

### 2. 类型检查

- `yarn check-types`

失败时：
- 只修**本次改动引入**的错误
- 既有的历史错误单独列给用户，不擅自修改

修完重跑，直到通过或只剩既有错误。

### 3. Lint

- `yarn lint --quiet`

处理策略同第 2 步。

### 4. 规范自查

读 `docs/coding-standards.md`，按 9 个维度对照本次改动逐项检查：

边界 / 测试 / UX / 性能 / 可维护性 / 安全 / 可观测性 / 韧性 / 模块化

**只报本次改动相关的问题**，不做全仓库审计。

### 5. 输出

```
| 维度 | 结果 | 说明 |
|------|------|------|
| 类型 | ✅/❌ | ... |
| Lint | ✅/❌ | ... |
| 边界 | ✅/⚠️/❌ | ... |
| ... | | |

结论：可提交 / 有 N 项需处理
```

## 约束

- 不自动 commit、不自动 push
- 不修改与本次改动无关的文件
- 检查通过也要说清"通过"，不要含糊
