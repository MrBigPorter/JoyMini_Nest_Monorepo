# 102 · 运营指标口径抽样核对（合成样本）

> 日期：2026-11-19
> 关联：`openspec/changes/reliable-ai-runtime` 6.2、[#85 生产化差距审计](./85-生产化差距审计与企业上线清单.md)
> 口径来源：`tools/ops/ai-quality-report.py`、`design.md` D5
> 结论：**20/20 一致（100%，门槛 ≥90%）**；本次为构造真值校准，不是生产流量抽样

---

## 1. 为什么用合成样本

本地库只有 4 条 SUPPORT/AI 会话，凑不够 20 条人工抽样。
经确认采用「本地造 20 条」：每条会话的标签在写入时就是已知的，
再用报告脚本的同一套 SQL 反算，逐条比对口径。

这能证明：**SQL 判定与文档定义一致**。
不能证明：真实用户分布下的误判率。后者需要等线上有 ≥20 条真实会话后再补一轮。

## 2. 构造覆盖

| 类型 | 条数 | 构造真值 |
|---|---:|---|
| 未转人工 + 有 AI 回复 | 10 | 独立解决 |
| 已转人工 + 有 AI 回复 | 4 | 未解决（其中 3 条带首响时间） |
| 已转人工 + 无 AI 回复 | 3 | 未解决（其中 2 条带首响时间） |
| 未转人工 + 无 AI 回复 | 3 | 未解决（AI 被问过但没答，不能从分母消失） |

## 3. 结果

```text
一致率：20/20 = 100%（门槛 ≥90%）
合成样本：会话 20，独立解决 10
首响 P95 25800 ms
转人工原因：ai_error、explicit_request、negative_sentiment
单会话 token：不可得（ai_usage_daily 无 conversation 维度）
```

- 独立解决率：10/20 = 50%，与构造一致
- 首响 P95：仅统计「已转人工且已首响」的 5 条，25800 ms 与构造的 21s/23s/25s 分布相符
- token 指标仍标注「不可得」，没有用近似值冒充
- 含首次「未转人工 + 无 AI 回复」的 3 条，验证它们计入分母而非被静默排除

## 4. 复现

```bash
python3 tools/ops/quality-sample-calibration.py        # 跑完自动清理
python3 tools/ops/quality-sample-calibration.py --keep # 保留样本供人工查看
```

脚本源码：[tools/ops/quality-sample-calibration.py](../../tools/ops/quality-sample-calibration.py)

## 5. 局限

- 构造样本只能验证口径，不覆盖真实会话里的噪声（多轮、撤回、人工插话）。
- 建议线上累计 ≥20 条真实 AI 会话后，用同一脚本的判定 SQL 再抽一轮人工复核。
