# 105 · RAG 相关性门卫验收

> 日期：2026-11-20
> 变更：`rag-relevance-gate`
> 数据：`tools/eval/rag/reports/20261120-011111.json`（topK=3，Jina rerank）
> 决策：**接受**——无关问题拦下 19/20，正常问题误拦 3/109

---

## 1. 规则

```
保留 = 关键词层有候选 OR rerank topScore ≥ RAG_RERANK_MIN_SCORE
```

- 默认阈值 **0.131**（由 20 道负样本与 109 道正样本校准）
- 只在 reranker 成功时生效；reranker 不可用走 RRF，不套用
- 关键词层命中是“属于知识库”的强信号，直接放行

## 2. 结果

| 指标 | 改前 | 改后 |
|---|---:|---:|
| 负样本误召回 | 20/20（100%） | **1/20（5%）** |
| 正样本 Hit@1 | 78.9% | 78.9% |
| 正样本 Hit@3 | 97.2% | **94.5%** |
| 正样本 MRR | 0.876 | 0.862 |

误拦的 3 道正样本：

- `r49 两张券能一起用吗`
- `r53 中奖后怎么领奖`
- `r67 密码忘了怎么改`

漏网的负样本：

- `n11 How do I cook pasta?` —— `cook` 以子串形式命中 `cookies`，被关键词层放行

## 3. 为什么接受

- 无关问题不再 100% 编造答案，误召回从 20 降到 1
- 代价是 3/109（2.8%）正常问题被拒；比预估多 1 题，已确认接受
- 失败原因集中在英文子串匹配，不是阈值本身；后续单独修 `ILIKE '%cook%'` 命中 `cookies` 的问题，不需要回滚门卫

## 4. 配置与回滚

```bash
# 关闭/调整门卫
RAG_RERANK_MIN_SCORE=0        # 关闭
RAG_RERANK_MIN_SCORE=0.131    # 默认
```

回滚：把阈值设为 0，或回退本次提交；不涉及数据库与数据迁移。

## 5. 后续

1. 英文关键词匹配改为词边界（避免 `cook` 命中 `cookies`），预计可救回 1 道负样本或 1 道正样本
2. 负样本扩到 ≥50 后再校准一次阈值
3. 观察线上 `relevanceGate.blocked` 比例，若误拦率 >5% 再调
