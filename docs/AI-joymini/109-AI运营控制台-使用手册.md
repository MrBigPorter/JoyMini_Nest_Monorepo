# 109 · AI 运营控制台使用手册

> 面向：客服运营、值班管理员
> 入口：admin → AI Operations

## 1. 先看哪里

| 想知道                   | 去哪里             |
| ------------------------ | ------------------ |
| AI 是否在正常处理        | `/ai-ops` Overview |
| 有没有死信/Outbox 积压   | `/ai-ops/runtime`  |
| 某个会话用了哪个流程版本 | `/ai-ops/flows`    |
| 今天 token 用了多少      | `/ai-ops/usage`    |
| 某个用户的记忆           | `/ai-ops/memory`   |

## 2. 用户说“AI 没回复”

1. 打开 `/ai-ops`，看 AI 队列 waiting/failed、Outbox FAILED
2. 打开 `/ai-ops/runtime`
   - 有 AI 死信：查看 failedReason，确认不是“已有 AI 回复”后点 Replay
   - 有 Outbox FAILED：点 Replay，等 5 秒刷新
3. 仍然没有回复：
   - 检查队列是否被 Pause
   - 检查会话是否已转人工（`handlerId != null` 时 AI 不处理）
   - 检查 token 配额是否超限（Usage 页）

## 3. 队列操作

- **Pause**：暂停消费，所有 AI 回复会停。只在确认故障范围后使用，必须二次确认。
- **Resume**：恢复消费。
- **Clean**：清理已完成/失败任务，默认保留 24h；不要清掉还需要排查的死信。

## 4. 重放规则

### AI 死信

- 后端用 `Job.retry()`，不会新建重复 job
- 已有 AI 回复的任务会被拒绝（避免工具副作用执行两次）
- 重放后看 `attemptsMade` 是否变化

### Outbox

- 只重放 FAILED
- PENDING/SENDING 是正常在途，不要手动重放
- 同一 `messageId` 入队幂等，不会产生第二条回复

## 5. 流程版本

- **Switch**：把某个会话切到目标定义版本
- **Rollback definition**：切回旧版本，只改绑定指针，不撤销已完成的退款/下单
- 拒绝原因：
  - `human_handling`：人工处理中
  - `thread_drift`：会话 thread 变了
  - `flow_in_progress`：流程还在填表/确认/查询
  - `pending_confirmation`：还有未消费的确认卡片
- 状态回滚（checkpoint）暂不在页面提供，需要研发执行

## 6. Token 用量

- 口径：仅 AI 客服主链路、成功流、UTC
- 不含 blog-ai、embedding、eval、失败/取消流
- `overDailyLimit` 只是标记，不会自动封禁

## 7. 用户记忆

- 查看需要 ADMIN/SUPER_ADMIN
- 删除需要 SUPER_ADMIN，且写操作日志
- 单条删除是软删（status=DELETED）；整用户删除是硬删
- 摘要区为空是正常的：当前摘要表还没有写入方

## 8. 不要做的事

- 不要用 Pause 代替排查
- 不要在没确认 `failedReason` 时批量重放
- 不要把 Usage 页当财务成本报表
- 不要以为前端隐藏按钮就是权限控制；以后端 403 为准
