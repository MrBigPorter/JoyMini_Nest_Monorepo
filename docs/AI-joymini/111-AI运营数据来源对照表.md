# 111 — AI 运营数据来源对照表

> 用途：查清每个 AI 页面上的数字从哪来，避免再用 SQL 造数。
> 配套手册：`docs/AI-joymini/110-真实测试账号全流程演练手册.md`

## 1. 一张图

```text
真实账号 OTP 注册
        │
        ▼
GET /chat/business ──► Conversation + aiMetadata.trafficSource
        │
        ▼
Socket send_message ──► ChatMessage(user) + ai_task_outbox
        │
        ▼
BullMQ ai-processing ──► LangGraph
        │
        ├─► ChatMessage(assistant, isAi)
        ├─► AiUsageDaily
        ├─► AiUserMemory / AiMemorySummary
        ├─► AiSecurityEvent
        ├─► flowState / contextState / pendingConfirm
        └─► 转人工 → handlerId + SLA
        │
        ▼
管理员操作 ──► AiAnswerFeedback / AiEvalDataset / Run / Result
故障演练   ──► BullMQ failed / ai_task_outbox FAILED
```

## 2. 页面 × 数据 × 真实动作

### 2.1 `/ai-ops` 总览

| 展示 | 数据表 / 来源 | 真实动作 | 备注 |
|---|---|---|---|
| 会话量 | `Conversation` | 真实 `/chat/business` | 只统计真实会话 |
| AI 回复量 | `ChatMessage` where `source='ai'` | 真实 Socket 提问 | 不手写 |
| 转人工数 | `Conversation.handlerId` | 用户说“转人工”或负面情绪 | 由 AI 判定 |
| 队列积压 | BullMQ `ai-processing` | 真实消息入队 | 故障时上升 |
| 失败数 | BullMQ failed / outbox | 故障演练 | 不伪造 |

### 2.2 `/ai-ops/runtime` AI Runtime

| 区块 | 数据来源 | 真实动作 | 能否靠用户流量产生 |
|---|---|---|---|
| 队列 | BullMQ `getJobCounts` | 发消息入队 | 能 |
| 死信 | `ai-processing` failed jobs | worker 抛错 / 超时 | 需故障演练 |
| Outbox | `ai_task_outbox` | `sendMessage` 事务写入 | 能 |
| Outbox FAILED | `ai_task_outbox.status='FAILED'` | Redis 停 / relay 重试耗尽 | 需故障演练 |
| Replay | `Job.retry()` / outbox 重放 | 管理员点击 | 管理员操作 |

禁止：直接 INSERT `ai_task_outbox` 制造 FAILED。

### 2.3 `/ai-ops/flows` AI Flow Versions

| 区块 | 数据来源 | 真实动作 |
|---|---|---|
| 定义版本 | `FlowDefinitionVersion` | 管理员创建/发布 |
| 会话绑定 | `ConversationFlowBinding` | 管理员 bind / switch |
| 审计日志 | `FlowBindingAuditLog` | 管理员切换/回滚 |
| 回滚 | checkpoint `getStateHistory` + `updateState` | 管理员点击 |

用户流量只能产生 `flowState`，不能产生版本和审计日志。

### 2.4 `/ai-ops/usage` AI Usage

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| 总 token | `AiUsageDaily` | 每轮真实 LLM 调用 `recordUsage` |
| 按用户 | `AiUsageDaily.userId` | 真实账号提问 |
| 按模型 | `AiUsageDaily.model` | 当前 DeepSeek 配置 |

禁止：手工 INSERT `AiUsageDaily`。

### 2.5 `/ai-ops/memory` AI Memory

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| 用户记忆 | `AiUserMemory` | 用户说“我叫小明/我来自上海/我已实名” |
| 记忆摘要 | `AiMemorySummary` | 达到阈值后后台生成 |
| 删除记忆 | `DELETE /admin/ai-memory/:id` | 管理员点击 |

白名单抽取，不是所有消息都会进记忆。

### 2.6 `/ai-ops/quality` AI Quality

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| 显式反馈 | `AiAnswerFeedback` | 管理员/用户在消息上点“有帮助/有误” |
| 分诊上下文 | `AiAnswerFeedback` + `ChatMessage` | 列表回查用户问题与被评价的 AI 回答 |
| 隐式负反馈 | 转人工/重复追问/放弃 | 真实会话行为 |
| 评测集 | `AiEvalDataset` / `AiEvalCase` | 管理员在页面创建 |
| 评测运行 | `AiEvalRun` / `AiEvalResult` | 管理员启动 |
| LLM Judge | `/admin/ai-eval/judge` | 管理员触发 |

显式反馈不能由脚本 INSERT；隐式反馈由真实行为产生。

### 2.7 `/ai-ops/security` AI Security

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| 注入事件 | `AiSecurityEvent` | `special_injection` 命中检测 |
| 类型分布 | `type` | 忽略指令/套提示词等 |
| 模式 | `mode` | `log` / `block` |

前置条件：`AI_INJECTION_DETECTION_MODE=log`（或 `block`）。

只存类型、长度、用户哈希、会话 ID，不存原文。

### 2.8 `/ai-ops/support` Support Ops

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| 等待趋势 | `Conversation` 转人工时间 | `special_transfer` 或用户要求 |
| 超时 | SLA 计算 | 转人工后未及时响应 |
| 会话列表 | `Conversation.handlerId` | 真实转人工 |

管理员关闭会话：`PATCH /admin/chat/conversations/:id/close`。

### 2.9 `/ai-ops/insights` AI Insights

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| 转人工原因 | 会话 + 反馈聚合 | 真实转人工 |
| 反馈分诊 | `AiAnswerFeedback` 聚合 | 管理员标注 |
| 趋势 | 按天聚合 | 持续跑流量 |

### 2.10 `/ai-ops/context` Context Debug

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| flowState | LangGraph checkpoint | 多轮流程推进 |
| contextState | `ConversationContextState` | 改口/指代/槽位 |
| pendingConfirm | Redis | 确认卡片生成 |
| 最近消息 | `ChatMessage` | 真实对话 |

用真实 `conversationId` 查询；没有真实会话就没有可看的内容。

### 2.11 `/customer-service` 客服工作台

| 展示 | 数据来源 | 真实动作 |
|---|---|---|
| 会话列表 | `Conversation` | 真实开客服 |
| SIM 标记 | `aiMetadata.trafficSource` | 模拟流量来源 |
| 消息 | `ChatMessage` | 真实 Socket |
| 转人工 | `handlerId` | AI 转人工 |
| 关闭 | `PATCH .../close` | 管理员操作 |

### 2.12 知识库 / Prompt / Intent Examples

| 页面 | 数据来源 | 真实动作 |
|---|---|---|
| `/knowledge` | `KnowledgeDocument` | 管理员上传/同步 |
| `/ai-prompt` | `AiPrompt` | 管理员编辑 |
| `/intent-examples` | `IntentExample` | 管理员维护 |

这些是配置数据，不是流量数据；不要用它们冒充对话数据。

## 3. 哪些数据只能管理员产生

| 数据 | 页面 | 原因 |
|---|---|---|
| 显式反馈 | `/ai-ops/quality`、`/customer-service` | 需要真人对回答判断 |
| 评测集/用例 | `/ai-ops/quality` | 需要人工写期望答案 |
| 评测运行 | `/ai-ops/quality` | 管理员主动触发 |
| 流程版本/绑定/审计 | `/ai-ops/flows` | 变更操作 |
| 关闭会话 | `/customer-service` | 运营动作 |
| 死信重放 | `/ai-ops/runtime` | 运维动作 |
| 记忆删除 | `/ai-ops/memory` | 隐私操作 |

## 4. 哪些数据只能故障演练产生

| 数据 | 演练 | 恢复 |
|---|---|---|
| Outbox PENDING 堆积 | 停 Redis 后发 HTTP `/chat/message`（Socket 会 ack 超时） | 启 Redis，等 relay |
| Outbox FAILED | relay 连续 8 次入队失败 | 管理员 Replay |
| BullMQ failed | 占住 `ai:conv:<id>` 锁，让 worker 等锁超时，真实重试耗尽 | 释放锁 + 管理员 Replay（2026-11-20 实测 1 条） |
| SLA 超时 | 转人工后不处理 | 管理员关闭 |
| 队列积压 | 降并发/停 worker | 恢复 worker |

生产环境不做故障演练。

## 5. 对账 SQL

只读，不写。

```sql
-- 本轮会话
SELECT count(*) FROM "Conversation"
WHERE ai_metadata->>'trafficSource' = 'simulation_support_v1';

-- 本轮 AI 回复
SELECT count(*) FROM "ChatMessage"
WHERE source = 'ai' AND "createdAt" > now() - interval '2 hours';

-- 转人工
SELECT count(*) FROM "Conversation"
WHERE handler_id IS NOT NULL
  AND ai_metadata->>'trafficSource' = 'simulation_support_v1';

-- 安全事件
SELECT type, count(*) FROM ai_security_events
WHERE created_at > now() - interval '2 hours'
GROUP BY type;

-- 用量
SELECT date, total_tokens FROM ai_usage_daily
WHERE date >= current_date - 1;

-- 记忆
SELECT count(*) FROM ai_user_memories
WHERE created_at > now() - interval '2 hours';

-- Outbox
SELECT status, count(*) FROM ai_task_outbox GROUP BY status;
```

字段名以实际 schema 为准；执行前先用 `\d` 确认。

## 6. 判定“数据是否可信”

一条数据可信，必须同时满足：

1. 有真实 `userId`
2. 有真实 `conversationId`
3. 时间落在本轮运行窗口
4. 能对应到 `events.jsonl` 里的场景
5. 不是 `diag_*`、`seed_*`、`test_*` 前缀
6. 不是手工 INSERT

不满足任意一条，就不能写进报告或面试材料。

## 7. 常见误区

| 误区 | 事实 |
|---|---|
| “页面有数字就是跑通了” | 数字可能来自种子行 |
| “有会话就有 AI 回复” | 可能转人工或队列失败 |
| “跑一次就有评测数据” | 评测必须管理员创建并运行 |
| “注入场景一定产生安全事件” | 需要检测开关打开且命中 |
| “确认卡片等于业务成功” | 卡片只是待确认，未执行 |
| “同一账号可以反复跑” | 转人工后该账号不再触发 AI |
