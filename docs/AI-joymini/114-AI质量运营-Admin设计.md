# 114 — AI 质量运营 Admin 设计

> 状态：设计稿
> 负责人：AI 质量运营 / 产品
> 更新时间：2026-11-21
> 关联文档：[112 文档规范](./112-AI质量运营-文档规范.md)、[113 数据模型](./113-AI质量运营-数据模型.md)、[115 AI Operations 运营化设计](./115-AI-Operations-运营化设计.md)、[116 页面结构与 UI](./116-AI-Operations-页面结构与UI规范.md)、[117 开源方案调研](./117-AI-Operations-开源方案调研.md)
> 关联页面：`/ai-ops/quality`
> 设计依据：LangSmith / Langfuse / Braintrust 的标注队列、评分卡、数据集回归；客服 QA 的 scorecard / calibration 实践

## 1. 设计目标

运营第一次打开页面，不需要培训就能完成：

```text
看一条真实对话
→ 判断有没有问题
→ 选一个原因
→ 点“保存并下一条”
```

不是让运营学习 `implicit/explicit/PENDING/score/JSON`。

## 2. 角色与任务

| 角色 | 每天要完成的事 | 不关心什么 |
|---|---|---|
| 运营 / 客服主管 | 处理待办、确认问题、排除噪声、把问题送进回归 | trace、ClickHouse、数据库 |
| 知识库管理员 | 看文档质量、查检索失败、补知识 | 评分模型、队列实现 |
| 工程师 | 看归因、复现、改 Prompt/检索、跑回归 | 运营话术、工单分配 |
| 负责人 | 看趋势、风险、是否变好 | 单条对话细节 |

## 3. 信息架构

`/ai-ops/quality` 改名为 **AI 质量**，三个工作区：

```text
AI 质量
├── 质量待办      运营每天用
├── 回归测试      工程师/运营主管用
└── 知识质量      知识库管理员用
```

入口按角色排序：

```text
运营登录 → 默认进入“质量待办”
工程师登录 → 默认进入“回归测试”
知识库管理员 → 默认进入“知识质量”
```

Phase 1 可以先不做角色默认页，但导航顺序必须是“质量待办 → 回归测试 → 知识质量”。

## 4. 质量待办

### 4.1 页面目标

让运营在 **30 秒内**判断一条反馈：

```text
是不是 AI 的问题？
是什么问题？
下一步做什么？
```

### 4.2 首页

```text
┌──────────────────────────────────────────────────────────────┐
│ AI 质量 · 质量待办                         [开始质检]         │
├──────────────────────────────────────────────────────────────┤
│ 待处理 5   模型问题 2   服务故障 3   误转 1   已进回归 1       │
├──────────────────────────────────────────────────────────────┤
│ 筛选：归因 [全部]  转人工原因 [全部]  时间 [近 7 天]           │
├──────────────────────────────────────────────────────────────┤
│ 今天                                                         │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 20:47  优惠券     模型问题？   待处理                    │ │
│ │ 用户：帮我看看有哪些优惠券可以领                          │ │
│ │ AI：抱歉，我这边暂时处理不了…已经帮你转接人工客服          │ │
│ │ [开始处理]                                               │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

KPI 不是装饰，必须能点：

- 待处理 → 过滤 `resolution=OPEN`
- 模型问题 → `failureKind=MODEL_ERROR`
- 服务故障 → `SERVICE_ERROR`
- 误转 → `UNEXPECTED_TRANSFER`
- 已进回归 → `resolution=ADDED_TO_EVAL`

### 4.3 质检卡：一次一条

不要默认大表格。点“开始质检”进入单条模式：

```text
┌──────────────────────────────────────────────────────────────┐
│ 第 3 / 20 条                                      [退出质检]  │
├───────────────────────────────┬──────────────────────────────┤
│ 完整对话                       │ 这条怎么判断？                │
│                               │                              │
│ 用户：帮我看看有哪些优惠券      │ 1. 回答是否正确？             │
│ AI：抱歉，我这边暂时处理不了…   │    ○ 正确  ○ 不正确  ○ 无法判断│
│ 用户：好的，麻烦你了            │                              │
│ AI：已经帮你转接人工客服        │ 2. 是否应该转人工？           │
│                               │    ○ 应该  ○ 不应该  ○ 用户要求│
│ [展开工具调用] [查看 RAG 来源]  │                              │
│                               │ 3. 主要原因                   │
│ 转人工原因：ai_error            │    ○ 模型答错                 │
│ 服务状态：AI 处理失败           │    ○ 知识缺失                 │
│                               │    ○ 检索没召回               │
│                               │    ○ 工具调用失败             │
│                               │    ○ 服务故障                 │
│                               │    ○ 用户明确要求转人工        │
│                               │    ○ 不该转人工               │
│                               │                              │
│                               │ 4. 备注 / 期望答案（可选）     │
│                               │ [__________________________] │
│                               │                              │
│                               │ [保存并下一条] [跳过] [排除]   │
└───────────────────────────────┴──────────────────────────────┘
```

### 4.4 评分卡：只保留 4 个判断

| 判断 | 类型 | 选项 | 用途 |
|---|---|---|---|
| 回答是否正确 | 三选一 | 正确 / 不正确 / 无法判断 | 判断模型质量 |
| 是否应该转人工 | 三选一 | 应该 / 不应该 / 用户明确要求 | 判断误转 |
| 主要原因 | 单选 | 模型答错 / 知识缺失 / 检索没召回 / 工具失败 / 服务故障 / 正常转人工 / 误转 | 归因 |
| 备注 / 期望答案 | 文本 | 可选 | 进回归用例 |

不要再加“语气 1-5 分”“格式 1-5 分”。维度超过 5 个，运营会开始乱选。

### 4.5 决策树

```text
用户是否明确要求转人工？
├── 是 → 正常转人工 → 排除
└── 否
    ├── 有 ai_error / 超时 / 队列失败？
    │   ├── 是 → 服务故障 → 排除，不计入模型质量
    │   └── 否
    │       ├── 用户只是礼貌收尾却转人工？
    │       │   ├── 是 → 误转人工 → 确认问题 → 加入回归
    │       │   └── 否
    │       │       ├── AI 答错 / 答非所问？
    │       │       │   ├── 是 → 模型答错 → 确认问题 → 加入回归
    │       │       │   └── 否
    │       │       │       ├── 知识库没有 / 检索没召回？
    │       │       │       │   ├── 是 → 知识问题 → 交知识库管理员
    │       │       │       │   └── 否
    │       │       │       │       └── 用户自己离开 → 排除
```

### 4.6 动作与状态

| 动作 | 结果状态 | 是否进模型质量 | 是否进回归 |
|---|---|---|---|
| 确认问题 | 已确认问题 | 是 | 可选 |
| 排除：服务故障 | 已排除 | 否 | 否 |
| 排除：正常转人工 | 已排除 | 否 | 否 |
| 加入回归 | 已加入回归 | 是 | 是 |
| 标记已修复 | 已修复待验证 | 是 | 是 |
| 关闭 | 已关闭 | 看归因 | 看归因 |

按钮文案不要再出现 `Reviewed / Ignore`。

### 4.7 键盘与效率

```text
J / K      下一条 / 上一条
1 / 2 / 3  选择当前问题的选项
Enter      保存并下一条
S          跳过
Esc        退出质检
```

### 4.8 批量模式

只对“明确同类”的条目开放：

```text
勾选多条 → [批量排除：服务故障]
```

不提供“批量确认模型问题”，避免误伤。

## 5. 回归测试

### 5.1 页面目标

让运营/工程师回答：

```text
这次改动有没有把旧问题改坏？
哪些是新增失败？
哪些已经修复？
```

### 5.2 首页

```text
┌──────────────────────────────────────────────────────────────┐
│ 回归测试                                      [+ 新建评测集]  │
├──────────────────────────────────────────────────────────────┤
│ 客服回归集 12 条    上次 10/12    本次 11/12    +1           │
│ [运行] [查看上次结果] [从反馈添加用例]                        │
├──────────────────────────────────────────────────────────────┤
│ 最近运行                                                     │
│ 11-21 11:02  11/12 通过   新失败 1   已修复 1   仍失败 2      │
│ 11-20 18:40  10/12 通过                                       │
└──────────────────────────────────────────────────────────────┘
```

### 5.3 运行结果

```text
本次 11/12 通过
├── 新失败 1
│   └── 用户说“好的，麻烦你了”，AI 却转人工
├── 已修复 1
│   └── 充值问题不再承诺直接充值
└── 仍失败 2
    ├── 优惠券列表为空
    └── 退款规定未引用知识库
```

分组比一张大表更容易让运营理解。

### 5.4 从反馈生成用例

在质检卡点“加入回归”：

```text
用户问题：帮我看看有哪些优惠券可以领
实际回答：抱歉，我这边暂时处理不了…
期望答案：列出可领取优惠券；如果为空，说明原因并给领取入口
期望要点：必须提到“优惠券中心”
来源：Feedback #xxx
```

只有“模型答错 / 误转 / 知识缺失 / 检索失败”可以生成用例。服务故障和正常转人工不能进回归。

### 5.5 高级模式

JSON 导入、`expect` 规则、judge 配置收进“高级模式”，默认不显示。

## 6. 知识质量

### 6.1 页面目标

回答：

```text
知识库本身有没有问题？
检索有没有召回？
```

### 6.2 两个分区

```text
知识质量
├── 文档质量
│   ├── 27 篇文档
│   ├── 优秀 22 / 良好 5 / 可疑 0
│   ├── 需要复核：4 篇截断
│   └── 文档列表：标题 / 分数 / flags / 版本 / 操作
└── 检索测试
    ├── 输入问题
    ├── 可选 domain
    ├── 结果表格：标题 / 分数 / 命中片段 / domain
    └── 说明：分数低 = 可能没召回
```

不要把 `byScore` 和 `recentFlags` 直接 `Object.entries` 成卡片；它们是嵌套对象。

### 6.3 检索结果

不要显示原始 JSON。用表格：

```text
排名 | 文档 | 分数 | 命中片段 | domain
1    | 退款政策 | 0.92 | “未发货订单可全额退款…” | order
2    | 售后说明 | 0.81 | “已发货订单需联系客服…” | order
```

如果 0 条命中，显示：

```text
没有召回结果。先检查：
1. 知识库是否有这篇文档
2. 文档是否已启用
3. domain 是否选错
4. 关键词是否太窄
```

## 7. 页面状态矩阵

| 页面 | 正常 | 空 | 错误 | 边界 | 加载 | 权限 | 中断恢复 |
|---|---|---|---|---|---|---|---|
| 质量待办 | 显示下一条 | “暂无待处理，去看回归测试” | 显示错误+重试，不显示空表 | 超长对话折叠，缺失回答显示“未生成” | 骨架屏 | 无权限显示申请入口 | 刷新后保留当前条目 |
| 回归测试 | 卡片+结果 | “还没有评测集，从反馈创建第一条” | 运行失败显示 summary.error | 0 用例禁止运行 | 运行中轮询+进度 | 只读隐藏运行按钮 | 刷新后继续轮询 |
| 知识质量 | 图表+表格 | “还没有文档，去知识库上传” | 统计失败显示重试 | 分数 null 显示“未检查” | 骨架屏 | 只读隐藏操作 | 保留筛选条件 |

### 功能未开启

`AI_FEEDBACK_UI_ENABLED=false` 时：

```text
反馈功能未启用
请联系管理员开启 AI_FEEDBACK_UI_ENABLED。
```

不要显示空表，让运营以为“没有反馈”。

## 8. 指标口径

| 指标 | 公式 | 运营解释 |
|---|---|---|
| 待处理 | `resolution=OPEN` | 今天还要看多少 |
| 服务故障率 | `SERVICE_ERROR / 全部反馈` | 系统稳定性 |
| 模型错误率 | `MODEL_ERROR / (MODEL_ERROR + UNEXPECTED_TRANSFER)` | AI 本身答得好不好 |
| 误转率 | `UNEXPECTED_TRANSFER / 全部转人工` | 转人工是不是太激进 |
| 正常转人工率 | `EXPECTED_TRANSFER / 全部转人工` | 该转的有没有转 |
| 回归通过率 | `solved / total` | 改动有没有变坏 |

服务故障和正常转人工不能进模型错误率分母。

## 10. 验收：用当前 8 条真实反馈

| 反馈 | 运营看到 | 判断 | 动作 |
|---|---|---|---|
| 21:07 `abandoned`，`好的，麻烦你了` | 转人工原因 `ai_error` | 服务故障 | 排除 |
| 20:59 `incorrect`，优惠券 | 转人工原因 `ai_error` | 服务故障 | 排除，不加入模型错误 |
| 20:59 `correct`，`谢谢你` | 回答正常 | 无需处理 | 关闭 |
| 20:54 `transferred`，`好的，麻烦你了` | 礼貌收尾却转人工 | 误转人工 | 确认问题，加入回归 |
| 20:47 `repeated_question`，提现 | 第一次要银行卡信息，第二次 `ai_error` | 先排除服务故障；槽位收集不算错 | 排除 |
| 20:19 `transferred`，`就是上次那个` | AI 说“我明白了”再转人工 | 可以转，但不应假装理解 | 确认问题或关闭 |
| 20:12 `transferred`，`找人工` | 用户明确要求 | 正常转人工 | 排除 |
| 20:10 `abandoned`，`在吗呢` | `ai_error` 兜底 | 服务故障 | 排除 |

验收标准：

```text
运营不需要问工程师，能在 30 秒内给每条一个动作。
```

## 11. 非目标

- 不做自动改 Prompt
- 不做完整工单系统（分派、SLA、评论流）
- 不做多租户
- 不做完整 Langfuse 替代品
- 不把 ClickHouse 引入当前阶段
- 不让运营直接编辑 JSON

## 12. 上线顺序

```text
1. 文档评审（112/113/114）
2. 数据模型评审（只评审，不迁移）
3. 后端只读 API：归因、处理结论、trace 摘要
4. 前端质量待办只读版
5. 开放单条处理
6. 开放“加入回归”
7. 回归测试改版
8. 知识质量改版
9. 用 8 条真实反馈验收
```

每一步都可以单独关闭，不影响现有 `/ai-ops/quality`。
