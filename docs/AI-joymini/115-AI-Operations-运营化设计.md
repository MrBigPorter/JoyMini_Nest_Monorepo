## 1. 执行摘要

AI Operations 现在不是“功能不够”，而是四个问题叠在一起：

```text
定位错了：工程控制台当成运营后台
数据错了：关键指标口径不对
安全漏了：前端不控权限，后端有接口没角色
体验断了：能看到问题，但看不到该做什么
```

一句话：

> 能排障，不能运营；数据能看，不能信；按钮能点，不知道后果。

本轮目标不是加页面，而是把 AI Operations 分成三层，并修正会误导运营的数据和安全问题。

## 2. 现状审计

### 2.1 系统性问题

| 问题 | 证据 | 影响 |
|---|---|---|
| 一个菜单混了三种人 | 10 个 `/ai-ops/*` 页面同一分组 | 运营看不懂，工程师不够用 |
| 错误状态伪装成空状态 | 多个页面不读 `useRequest().error` | 接口挂了显示“暂无数据” |
| 前端不管角色 | VIEWER 看到 Pause/Replay/Delete/Switch | 点了 403 或误操作 |
| 关键指标口径错 | 今日 Token、Over limit、SLA | 运营做出错误判断 |
| 页面重复 | 两个 Feedback、三处 Token | 数字对不上 |
| 原始术语直出 | `ai_error`、`flowType`、hash、JSON | 运营无法理解 |

### 2.2 逐页现状

| 页面 | 现在是什么 | 核心问题 |
|---|---|---|
| Overview | 8 张卡 + 4 个入口 | 3 张死卡，指标重复，不能下钻 |
| Runtime | 队列/死信/Outbox | 静默成功、Clean 删死信、原始枚举 |
| Flows | 版本/绑定/审计 | Rollback 名字误导，手输 conversationId |
| Usage | token 汇总 | 无成本/预算/趋势，超限口径错 |
| Memory | 记忆表 | 手输 userId，来源不展示，硬删全部 |
| Quality | 反馈/评测/RAG | 已开始重做；Feedback 仍偏工程 |
| Security | 注入事件表 | 无分页/日期/处置，summary 不刷新 |
| Support | SLA 趋势 | 只有趋势，没有队列和负责人 |
| Insights | 8 个数字 | 无对比、无下钻、枚举未翻译 |
| Context | raw checkpoint JSON | 工程调试器，运营看不懂 |

## 3. 角色与任务

| 角色 | 每天要回答 | 应看到的页面 |
|---|---|---|
| 运营 / 客服主管 | 今天哪里不对、这条怎么处理 | 今日运营、质量待办、转人工队列 |
| 知识库管理员 | 知识缺不缺、检索准不准 | 知识质量、检索测试 |
| 工程师 | 为什么错、怎么复现、改完有没有坏 | Runtime、Flows、Context、Usage |
| 安全 / 合规 | 有没有攻击、要不要拦截 | 安全事件 |
| 负责人 | 质量、成本、风险趋势 | 运营洞察 |

## 4. 目标信息架构

### 第一层：今日运营

只回答“今天哪里不对”。

```text
AI Operations
├── 今日运营
│   ├── 异常卡
│   ├── 待处理反馈
│   ├── SLA 超时
│   └── 回归通过率
```

### 第二层：业务运营

```text
├── 业务运营
│   ├── 质量待办
│   ├── 转人工队列
│   ├── 知识质量
│   └── 回归测试
```

### 第三层：工程控制台

```text
└── 工程控制台
    ├── Runtime
    ├── Flows
    ├── Context
    ├── Usage
    ├── Memory
    └── Security
```

运营默认只看到第一、二层；工程控制台按角色显示。

## 5. 页面责任矩阵

| 页面 | 回答的问题 | 主要角色 | 可写 | 失败时 |
|---|---|---|---|---|
| 今日运营 | 今天哪里不对 | 运营/负责人 | 否 | 显示异常+重试，不显示零 |
| 质量待办 | 这条反馈怎么处理 | 运营 | 是 | 显示功能未开启/权限不足 |
| 回归测试 | 改完有没有变坏 | 运营/工程 | 是 | 显示运行失败原因 |
| 知识质量 | 知识库和检索是否可靠 | 知识库管理员 | 部分 | 显示文档/检索错误 |
| 转人工队列 | 谁在等、谁负责 | 客服主管 | 是 | 显示队列不可用，不留旧值 |
| Runtime | AI 是否在处理、失败在哪 | 工程 | 是 | 显示 Redis/队列错误 |
| Flows | 这个会话用哪版流程 | 工程 | 是 | 显示拒绝原因 |
| Context | AI 为什么这样回答 | 工程 | 否 | 显示具体失败原因 |
| Usage | 用了多少、花了多少 | 工程/负责人 | 否 | 显示口径与时间范围 |
| Memory | AI 记住了什么 | 工程/隐私管理员 | 是 | 显示无权限或接口失败 |
| Security | 有没有攻击、怎么处置 | 安全/工程 | 是 | 显示摘要/列表错误 |
| 运营洞察 | 趋势和异常是什么 | 负责人 | 否 | 显示错误，不显示零 |

## 6. 关键数据口径修正

### 6.1 今日 Token

现在：Overview 的“今日 Token”请求没有日期，后端默认 30 天。

修正：

```text
今日 Token = 当天 00:00–24:00（明确时区）
卡片必须显示“今日”与时间范围
```

### 6.2 Over limit

现在：所选区间总 token 对比每日限额。

修正：

```text
按天判断：某一天 totalTokens > AI_DAILY_TOKEN_LIMIT
区间视图显示“有 N 天超限”，不是“这个人超限”
```

### 6.3 SLA

现在：取窗口内最旧 2000 条；latest 来自另一条查询。

修正：

```text
取最新 N 条
图表、表格、卡片使用同一时间窗口
显示 SLA 阈值和数据截止时间
```

### 6.4 转人工率

现在：显示 `0.545`。

修正：

```text
显示 54.5%
同时显示分子/分母：12 / 22
显示时间范围
```

### 6.5 误转率 / 服务故障率

```text
服务故障率 = SERVICE_ERROR / 全部反馈
模型错误率 = MODEL_ERROR / (MODEL_ERROR + UNEXPECTED_TRANSFER)
误转率     = UNEXPECTED_TRANSFER / 全部转人工
```

服务故障和正常转人工不进入模型错误率。

## 7. P0：正确性与安全

### 7.1 权限

- `PATCH /admin/chat/conversations/:id/handler` 加 `@Roles`
- 前端按角色隐藏写操作
- 403 不再静默；显示“无权限，请联系管理员”
- Memory 读取权限与导航一致

### 7.2 Runtime 安全

- Pause/Resume 检查 `success:false`
- Clean 前显示：
  - 删除 completed 多少
  - 删除 failed 多少
  - 保留窗口
- Clean 默认只清 completed，不清 failed；清 failed 需要单独危险操作
- 重放前显示任务影响：会话、消息、是否已有回复

### 7.3 错误状态

所有页面必须区分：

```text
加载中
真无数据
无权限
功能未开启
接口失败
```

不允许用“暂无数据”覆盖后四种。

### 7.4 Feedback 开关

统一为一个变量：

```text
AI_FEEDBACK_UI_ENABLED
```

前端只读同一个公开开关；后端 GET 不再被写开关挡住，或明确区分读/写开关。

### 7.5 合并 Feedback

只保留一个运营入口：`/ai-ops/quality` 的质量待办。

`/ai-feedback` 改成：

- 导出/历史查询
- 或重定向

导出必须支持全量筛选结果，不是当前页 20 条。

## 8. P1：运营化改造

1. 今日运营首页：异常卡优先，不再 8 张静态卡
2. 质量待办：一次一条，4 个判断
3. 转人工队列：谁在等、等多久、谁负责、为什么转
4. 知识质量：文档质量 + 检索测试
5. 安全事件：确认攻击/误报/拦截
6. 客户记忆：用户搜索、来源、软删恢复
7. 用量与成本：趋势、预算、告警
8. 会话上下文：摘要 + 时间线，JSON 折叠
9. 流程版本：当前→目标→影响→原因

## 9. P2：平台化

- 成本预算告警
- 自定义 dashboard

- 多环境/灰度

## 10. 运营节奏

### 每天

```text
看今日运营异常
→ 处理质量待办
→ 看转人工队列
→ 看知识质量异常
```

### 每周

```text
看运营洞察趋势
→ 选 3 条真实问题进回归
→ 跑一次回归
→ 看通过率变化
```

### 每次改 Prompt/知识库

```text
先跑回归
→ 通过率不能下降
→ 再发布
```

## 11. 验收

- [ ] 运营能在 30 秒内判断一条反馈
- [ ] 运营不需要理解 `ai_error`、hash、checkpoint
- [ ] 所有页面失败时不再显示“暂无数据”
- [ ] VIEWER 看不到写操作
- [ ] 今日 Token 真的是今天
- [ ] Over limit 按天判断
- [ ] SLA 图表与卡片同一时间窗口
- [ ] 两个 Feedback 只剩一个运营入口
- [ ] 每个页面都有明确下一步或“只读”

## 12. 非目标

- 不写代码
- 不引入 ClickHouse
- 不做完整 Langfuse 替代品
- 不做工单系统
- 不做多租户
- 不改现有业务表

## 13. 交接生命周期（2026-11-22）

转人工不再只显示队列，还明确四态与回 AI 策略：

- 状态：`AI_ACTIVE / WAITING_HUMAN / HUMAN_ACTIVE / CLOSED`
- 排队 10 分钟无人认领、坐席 60 分钟无回复 → 自动回 AI
- 回 AI 保留上下文但重置连续失败计数，写系统消息
- 转人工前检查在线客服；无人在线时留在 AI 并记录 `handoffCallback`
- 关闭后用户再发消息 → 同会话重开

细节见 [交接生命周期设计](../superpowers/specs/2026-11-22-ai-human-handoff-lifecycle-design.md)。
