## 🎯 本步骤目标

1. 商品评论数据反写 —— 将 `averageRating` + `reviewCount` 缓存到 `Treasure` 表
2. Admin 评论统计面板 —— 审核效率、评分分布、趋势等指标
3. AI 审核质量监控 —— 追踪人工对 AI 审核结果的覆盖情况

完成本步骤后，运营人员可以看到评论系统的核心指标，并能监控 AI 审核的准确性。

## 📖 开发背景

### 承上：上一步做了什么？

[27-创建-Flutter评论UI.md](27-创建-Flutter评论UI.md) 完成了：
- Flutter 评论列表组件（星级 + 分页 + 排序）
- 评论提交表单（星级选择 + 文字 + 图片）
- "有帮助"按钮交互

### 这一步要解决的问题

评论功能已经完整跑通了（创建 → AI 审核 → 管理后台审核 → Flutter 展示），但还缺少：
1. **商品维度数据**：产品详情页没有展示平均评分和评论数，Treasure 表也没有缓存这些统计
2. **运营指标**：Admin 后台看不到评论相关的统计（审核通过率、评分趋势、评论量趋势等）
3. **AI 质量闭环**：无法知道 AI 审核的准确率 —— 如果管理员经常反转 AI 的决定，说明 AI 模型需要调整

### 设计决策

| 决策点 | 选项 | 选择 | 原因 |
|--------|------|------|------|
| 评分反写时机 | 实时 / 定时任务 | **实时（Service 层事件触发）** | 评论操作频率不高，实时计算即可，无需额外延迟 |
| 反写计算方式 | 每次全量聚合 / 增量更新 | **全量聚合（Prisma aggregate）** | 数据量小（单个商品的评论数有限），全量聚合保证一致性 |
| 统计接口缓存 | 每次都查数据库 / 缓存 5 分钟 | **in-memory cache 5 分钟** | 数据更新频率低，避免每次打开面板都查库 |
| 质量监控实现 | 独立表 / 日志分析 | **独立表 `ModerationAuditLog`** | 追踪每次审核覆盖事件，支持回溯分析 |
| 趋势图组件 | 自建 recharts / 嵌入 iframe | **复用现有 `AnalyticsTrendSection` 的 recharts** | 项目已有 recharts 集成，保持一致性 |

### Step 1: 给 Treasure 表添加评分反写字段

**文件**: [`apps/api/prisma/schema.prisma`](../../apps/api/prisma/schema.prisma)

在 `model Treasure` 末尾（`@@index` 之前）添加两个字段：

```prisma
/// 平均评分（仅计算 APPROVED 评论）
averageRating Float? @default(0) @map("average_rating")
/// 评论总数（仅计算 APPROVED 评论）
reviewCount   Int    @default(0) @map("review_count")
```

**说明**：
- `averageRating` 使用 `Float?` 而不是 `Decimal`，因为评分是 1-5 的整数平均，Float 精度足够
- `reviewCount` 只计数 `status = APPROVED` 的评论，不统计 PENDING/REJECTED/FLAGGED
- 字段使用 `?` 可空，兼容已有商品没有评论的情况
- `@default(0)` 确保新字段自动初始化为 0

```typescript
// 调用时机：review 状态变为 APPROVED / 从 APPROVED 改为其他状态 / review 被删除

private async syncTreasureRating(treasureId: string): Promise<void> {
  const aggregation = await this.prisma.productReview.aggregate({
    where: {
      treasureId,
      status: ProductReviewStatus.APPROVED,
    },
    _avg: { rating: true },
    _count: { rating: true },
  });

  await this.prisma.treasure.update({
    where: { treasureId },
    data: {
      averageRating: aggregation._avg.rating ?? 0,
      reviewCount: aggregation._count.rating ?? 0,
    },
  });
}
```

**调用点**（在 Service 中已有的方法内追加）：

| 方法 | 调用时机 | 额外逻辑 |
|------|----------|----------|
| `create()` 之后 | 如果 AI 直接 APPROVED | 同步调用 |
| `update()` 之后 | 内容变更不影响评分，无需调用 | — |
| `supplement()` 之后 | 补充图片/视频，无需调用 | — |
| `audit()`（Admin 审核） | 状态从非 APPROVED → APPROVED 或反之 | 条件调用 |
| `remove()` | 删除已 APPROVED 的评论 | 条件调用 |
| `markHelpful()` | 不影响评分 | — |

**设计要点**：
- 此方法在 Service 层同步执行，不经过队列 —— 因为操作频率低、计算量小
- 如果将来评论量大，可改为 Bull 队列异步处理（但当前阶段不需要）

```typescript
async getStats(): Promise<ProductReviewStatsDto> {
  // 1. 按状态统计总数
  const statusCounts = await this.prisma.productReview.groupBy({
    by: ['status'],
    _count: { reviewId: true },
  });

  // 2. 整体评分分布
  const ratingDistribution = await this.prisma.productReview.groupBy({
    by: ['rating'],
    where: { status: ProductReviewStatus.APPROVED },
    _count: { reviewId: true },
    orderBy: { rating: 'asc' },
  });

  // 3. AI 审核通过率
  const totalModerated = await this.prisma.productReview.count({
    where: { aiModerated: true },
  });
  const totalApproved = await this.prisma.productReview.count({
    where: { aiModerated: true, status: ProductReviewStatus.APPROVED },
  });

  // 4. 最近 7 天评论趋势
  const sevenDaysAgo = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000);
  const recentReviews = await this.prisma.productReview.findMany({
    where: { createdAt: { gte: sevenDaysAgo } },
    select: { createdAt: true, status: true },
    orderBy: { createdAt: 'asc' },
  });

  // 5. 最有帮助的 Top 10
  const mostHelpful = await this.prisma.productReview.findMany({
    where: { status: ProductReviewStatus.APPROVED },
    orderBy: { helpfulCount: 'desc' },
    take: 10,
    select: {
      reviewId: true,
      content: true,
      rating: true,
      helpfulCount: true,
      user: { select: { nickname: true } },
    },
  });

  // 转换趋势数据为按天聚合
  const trendMap = new Map<string, { total: number; approved: number }>();
  for (const r of recentReviews) {
    const day = r.createdAt.toISOString().slice(0, 10);
    const entry = trendMap.get(day) || { total: 0, approved: 0 };
    entry.total++;
    if (r.status === ProductReviewStatus.APPROVED) entry.approved++;
    trendMap.set(day, entry);
  }

  return {
    totalReviews: statusCounts.reduce((sum, s) => sum + s._count.reviewId, 0),
    byStatus: Object.fromEntries(
      statusCounts.map((s) => [s.status, s._count.reviewId])
    ),
    ratingDistribution: Object.fromEntries(
      ratingDistribution.map((r) => [r.rating, r._count.reviewId])
    ),
    aiPassRate: totalModerated > 0 ? totalApproved / totalModerated : 0,
    weeklyTrend: Array.from(trendMap.entries()).map(([date, counts]) => ({
      date,
      ...counts,
    })),
    mostHelpful: mostHelpful.map((r) => ({
      id: r.reviewId,
      content: r.content.slice(0, 100),
      rating: r.rating,
      helpfulCount: r.helpfulCount,
      author: r.user.nickname,
    })),
  };
}
```

```tsx
function calcAverageRating(dist: Record<number, number>): string {
  let total = 0, count = 0;
  for (const [star, cnt] of Object.entries(dist)) {
    total += Number(star) * cnt;
    count += cnt;

  return count > 0 ? (total / count).toFixed(1) : '0.0';
}
```

### Step 5: 实现 AI 审核质量监控（ReviewLoopController）

**背景**：AI 审核不是"一次性设置就完事"的。如果管理员经常把 AI `APPROVED` 的评论改为 `REJECTED`，说明 AI 模型偏宽松；反之亦然。需要追踪这些"覆盖事件"并计算一致率。

#### 5a. 创建审核日志表

**文件**: [`apps/api/prisma/schema.prisma`](../../apps/api/prisma/schema.prisma)

```prisma
/// AI 审核质量追踪日志
model ModerationAuditLog {
  id            String   @id @default(cuid()) @map("id") @db.VarChar(32)
  createdAt     DateTime @default(now()) @map("created_at")
  reviewId      String   @map("review_id") @db.VarChar(32)
  aiDecision    String   @map("ai_decision") @db.VarChar(20)   /// AI 给的结果: APPROVED/FLAGGED/REJECTED
  aiScore       Float    @map("ai_score")                       /// AI 评分 0-100
  adminAction   String   @map("admin_action") @db.VarChar(20)  /// 管理员最终操作: APPROVED/REJECTED
  adminId       String   @map("admin_id") @db.VarChar(32)
  isOverride    Boolean  @map("is_override")                    /// adminAction != aiDecision 时为 true
  reason        String?  @map("reason") @db.VarChar(500)

  @@index([reviewId], map: "idx_mod_audit_review")
  @@index([createdAt], map: "idx_mod_audit_created")
  @@map("moderation_audit_logs")
}
```

**注意**：此表在 Step 25 的 `audit()` 方法中写入。在 Admin 审核接口中，当管理员执行 `approve` / `reject` 时，对比 AI 的原始决定，若不一致则 `isOverride = true`。

#### 5c. 添加质量监控统计端点

在 `ProductReviewAdminService` 中添加：

```typescript
async getModerationQuality(): Promise<ModerationQualityDto> {
  const logs = await this.prisma.moderationAuditLog.findMany({
    orderBy: { createdAt: 'desc' },
    take: 1000,
  });

  const totalLogs = logs.length;
  const overrides = logs.filter((l) => l.isOverride).length;

  // 按日聚合一致率
  const dailyMap = new Map<string, { total: number; overrides: number }>();
  for (const log of logs) {
    const day = log.createdAt.toISOString().slice(0, 10);
    const entry = dailyMap.get(day) || { total: 0, overrides: 0 };
    entry.total++;
    if (log.isOverride) entry.overrides++;
    dailyMap.set(day, entry);
  }

  return {
    consistencyRate: totalLogs > 0 ? (totalLogs - overrides) / totalLogs : 1,
    totalAudited: totalLogs,
    totalOverrides: overrides,
    dailyTrend: Array.from(dailyMap.entries()).map(([date, d]) => ({
      date,
      consistencyRate: d.total > 0 ? (d.total - d.overrides) / d.total : 1,
      total: d.total,
    })),
    recentOverrides: logs
      .filter((l) => l.isOverride)
      .slice(0, 10)
      .map((l) => ({
        id: l.id,
        reviewId: l.reviewId,
        aiDecision: l.aiDecision,
        adminAction: l.adminAction,
        reason: l.reason,
        createdAt: l.createdAt,
      })),
  };
}
```

   - 验证 `aiPassRate` 在 0-1 之间

3. **质量监控**：
   - 管理员审核一条评论，且结果与 AI 建议不同 → `ModerationAuditLog` 表新增记录，`isOverride = true`
   - 如果结果与 AI 建议一致 → `isOverride = false`
