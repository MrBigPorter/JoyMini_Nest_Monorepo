## 缺失项补充文档

### 缺 #06：工具/第三方 API 调用不稳定

当前状态：各 tool 函数有 try-catch，但无统一重试机制。

**推荐方案：**
1. 在 [`tool-registry.service.ts`](../../apps/api/src/client/ai-customer/graph/tools/tool-registry.service.ts) 中封装 `withRetry(fn, options)` 高阶函数
2. 支持指数退避重试（exponential backoff）：首次失败等 1s，第二次等 2s，第三次等 4s
3. 超时控制：每个工具调用设置 `AbortController.timeout(10000)`
4. 熔断器：连续失败 N 次后暂时禁用该工具

### 缺 #09：结构化输出给下游节点

当前状态：`AgentNodeOutput` 是 TS 接口，无运行时校验。

**推荐方案：**
1. 在 [`agent-types.ts`](../../apps/api/src/client/ai-customer/graph/types/agent-types.ts) 中添加 Zod schema
2. `answerSynthesizer` 在读取 `taskResults` 前做 Zod 校验
3. 校验失败时返回 fallback 消息而非崩溃

### 缺 #13：中间步骤结果展示

当前状态：后端 `agentSteps` 已存数据。

**推荐方案：**
1. 在前端 `useAiChat` Hook 中解析 `agentSteps` 事件
2. 展示工具调用过程（如"正在查询订单..." + spinner）
3. 参考 SDD F-26 可视化规划

### 缺 #15：多步骤延迟累积

**推荐方案：**
1. 在 `llm-factory.ts` 中添加耗时追踪
2. 每个节点执行前后记录时间戳
3. 在 `debug` 模式下返回耗时数据

### 缺 #16：多次模型调用成本叠加

**推荐方案：**
1. LangChain 的 `callbacks` 可以统计 token 使用量
2. 在 `AiCustomerService` 中注册 callback，收集每次 LLM 调用的 token 数
3. 存入数据库或日志，便于分析

## 方案 B 变更说明

### 背景

方案 B（单轮单 Agent）是企业标准 Router Pattern：

```
用户输入 → 意图分类 → 选一个 Agent → 执行 → 验证 → 输出
                      → 如果涉及多个领域 → 拆成多次对话
```

### 对 16 挑战的影响

| # | 挑战 | 方案 B 影响 |
|:-:|------|-----------|
| 04 | 并行节点与结果合并 | 不再需要，每个 turn 只执行一个 Agent |
| 10 | 工具选择与参数生成错误 | **彻底解决**——消除 supervisor LLM 分解环节，从根因杜绝幻觉 |
| 03 | 循环节点与终止条件 | supervisor 降级为 pure round counter，不再有 LLM 循环风险 |
| 02 | 条件分支与动态路由 | intentRouter 不再返回 `supervised` 意图，路由简化 |

### 执行示例

**用户：** "购买商品订单和优惠券"

```
Turn 1:
  intentRouter 检测到 order + coupon 两个领域
  → 输出 intent='order'（主意图）
  → orderAgent 执行：查订单
  → answerSynthesizer：显示订单结果 + "您还想了解优惠券信息吗？"

Turn 2:
  用户："看看有什么优惠券"
  → intentRouter 输出 intent='coupon'
  → couponAgent 执行：查优惠券
  → answerSynthesizer：显示优惠券结果
```
