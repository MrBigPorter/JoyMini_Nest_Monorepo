## 二、后端挑战详细分析

### #01 多轮对话上下文丢失 ✅

**核心技术栈：**

| 技术 | 文件 | 作用 |
|------|------|------|
| MemorySaver Checkpointer | [`customer.graph.ts`](../../apps/api/src/client/ai-customer/graph/customer.graph.ts:80) | 跨调用持久化 state |
| intentGateway | [`customer.graph.ts`](../../apps/api/src/client/ai-customer/graph/customer.graph.ts:30) | FLOW_INTENTS 缓存跳过路由器 |
| currentMessages slice | [`wallet-agent.node.ts`](../../apps/api/src/client/ai-customer/graph/nodes/wallet-agent.node.ts:117) | 6 条消息窗口限制 |
| 双重重置 | [`intent-router.node.ts`](../../apps/api/src/client/ai-customer/graph/nodes/intent-router.node.ts) + [`answer-synthesizer.node.ts`](../../apps/api/src/client/ai-customer/graph/nodes/answer-synthesizer.node.ts) | Bug 4 修复：taskResults 新轮次重置 |

**修复历史：**

| 问题 | 根因 | 修复 |
|------|------|------|
| Agent 节点返回 `state.messages` 而非 `currentMessages` | ToolMessage 丢失 | 改为 `currentMessages.slice(1)` |
| taskResults 跨轮污染 | merge reducer `{...a,...b}` 不删旧 key + MemorySaver 持久化 | intentRouter + answerSynthesizer 双重重置 |
| 多轮意图分类失败 | Context-free Intent Classification | intentGateway + FLOW_INTENTS 模式 |

**需改进：** 生产环境需从 MemorySaver 迁移到 PostgreSQL Checkpointer（#18 文档）。

### #03 上下文越长 token 成本和首字延迟 ⚠️

**当前实现：**

```typescript
// 各 Agent 节点中限制对话历史窗口
const currentMessages = [system, ...state.messages.slice(-6)];
```

**分析：**

| 维度 | 当前状态 | 风险 |
|------|:--------:|------|
| 消息窗口 | 6 条 | 过短可能丢失上下文，过长增加成本 |
| Token 监控 | ❌ 未实现 | 无法量化成本 |
| 首字延迟 | ❌ 未测量 | 无性能基准线 |
| 长上下文优化 | ❌ 未实现 | 无滑动窗口压缩 |

**参考方案：**

```
短对话（<6条）→ 全部保留
长对话（>6条）→ 滑动窗口 + 历史摘要压缩
极限对话（>50条）→ 丢弃历史，仅保留最新摘要
```

### #04 多轮对话里的指代消解 ⚠️

**当前实现：** intentGateway 通过 `FLOW_INTENTS` 缓存意图，跳过 intentRouter 重新分类。

**此前 Bug 记录：**

| Turn | 用户输入 | 原结果 | 修复后 |
|------|----------|--------|--------|
| 3 | "9977773453455"（银行卡号） | `order` ❌ | `wallet` ✅（Gateway 跳过路由器） |
| 4 | "porter"（账户名） | `user` ❌ | `wallet` ✅（Gateway 跳过路由器） |

**局限：** FLOW_INTENTS 仅缓存 4 个意图（order/wallet/rag/supervised）。非缓存的意图（coupon/user 等）每次仍走 LLM 分类。

### #10 幻觉问题（业务问答场景） ✅

**核心问题：** Bug 5 — Supervisor LLM 将"购买商品订单和优惠券"分解为 `[walletAgent, orderAgent, generalChat]`（应分解为 `[orderAgent, couponAgent]`）。

**3 层防御架构：**

```
Layer 1: Prompt 约束
  └─ 意图分类 prompt 明确排除规则 + 安全退出指令
Layer 2: 检索约束
  └─ RAG 分数阈值：低于阈值 → 不返回结果（而非编造）
Layer 3: 规则验证
  └─ 工具返回结果校验：金额是否匹配、订单号是否存在
```

**方案 B（企业标准 Router Pattern）：**

```
输入 → 意图分类 → 选择 ONE Agent → 执行 → 验证 → 输出
多领域需求 → 拆成多次对话
```

### #11 重复问题反复消耗 token（语义缓存）❌

**现状：** 未实现。

**方案思路：**

```
用户输入 → 语义向量生成（embedding）
  └─ 缓存命中（相似度 > 0.95）→ 直接返回缓存结果
  └─ 缓存未命中 → intentRouter 正常流程 → 存入缓存
```

**涉及文件：** 新建 `semantic-cache.ts` + `AiService.generateEmbedding()` 复用。

### #12 多模型切换与降级 ⚠️

## 六、面试话术

### Q1：你们怎么解决多轮对话上下文丢失？

```
两种机制：
1. MemorySaver Checkpointer — LangGraph 内置，通过 thread_id 跨调用持久化 state
2. intentGateway + FLOW_INTENTS — 多轮对话跳过意图分类步骤，直接路由到缓存意图的 Agent
```

### Q2：流式输出怎么实现的？遇到什么问题？

```
用的 SSE 协议 + Observable。后端分两种情况：
- 非流式：testChat API 一次性返回完整结果
- 流式：chatStream API 用 SSE 逐 token 推送

目前流式端点待实现。计划用 NestJS 的 @Sse() 装饰器，配合 LangGraph 的 streamEvents 逐事件推送。
```

### Q3：你们怎么处理 LLM 幻觉？

```
3 层防御：
1. Prompt 约束 — 意图分类 prompt 明确排除规则
2. 检索约束 — RAG 分数阈值，低于阈值不返回
3. 规则验证 — 工具返回结果做业务校验

最终方案：采用企业标准 Router Pattern（方案 B），每轮只处理一个领域，从架构层面消除幻觉。
```

### Q4：对话历史越长，token 成本怎么控制？

```
当前：messages.slice(-6) 限制窗口

规划：
- 短对话（<6条）→ 全部保留
- 长对话（>6条）→ 滑动窗口 + 历史摘要压缩
- 极限对话（>50条）→ 丢弃历史，仅保留最新摘要
```
