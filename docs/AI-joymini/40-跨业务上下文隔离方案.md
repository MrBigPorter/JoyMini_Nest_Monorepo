## 1. 问题

当用户完成一个业务后（如取款），切换到另一个业务（如查询优惠券）时，上一轮的 `flowData` 不会被清除，导致新业务 Agent 能看到上轮业务的残留数据。

### 实际表现

```
Round 1: 用户说「我要取款 500」
  → walletAgent: flowType=WITHDRAWAL, flowData={amount:500}
Round 2: 用户说「确认取款」
  → walletAgent: flowStatus=COMPLETED, flowData={amount:500}
Round 3: 用户说「帮我查优惠券」
  → intentRouter: classified as 'coupon'
  → 但是 flowData 仍然是 {amount:500}（残留数据）
  → couponAgent 虽然不用 flowData，但 flowData 被带到错误业务上下文中
```

---

## 2. 根因分析

### P1: [`state.ts`](apps/api/src/client/ai-customer/graph/state.ts:126) — `flowData` reducer 无法清空

```typescript
// 当前实现（第 127-130 行）
flowData: Annotation<Record<string, any>>({
  reducer: (a: Record<string, any>, b: Record<string, any>) => ({
    ...a,
    ...b,   // merge 模式 — 只能追加，不能清空
  }),
  default: () => ({}),
}),
```

即使某个 Node 返回 `flowData: {}`，reducer 也会把它 merge 到现有数据上，结果不变。对比 [`taskResults`](apps/api/src/client/ai-customer/graph/state.ts:82) 的正确模式：

```typescript
// taskResults reducer（第 81-84 行）— 正确做法
reducer: (a, b) => {
  if (Object.keys(b).length === 0) return {};  // 空对象 = 清空
  return { ...a, ...b };
},
```

**`flowData` 缺少空对象检测逻辑。**

### P2: [`intent-router.node.ts`](apps/api/src/client/ai-customer/graph/nodes/intent-router.node.ts:303) — 未检测话题切换

当前 `intentRouter` 每次执行都会覆盖 `flowType/flowStatus/taskResults/agentSteps`，但**没有检测当前 `state.flowType` 和新 intent 是否属于不同业务域**。

```typescript
// 当前实现（第 303-313 行）— 没有话题切换检测
const matchedFlowType = intentToFlowType(finalIntent);
return {
  intent: finalIntent,
  routeCache: finalIntent,
  flowType: matchedFlowType,
  flowStatus: getInitialStatus(matchedFlowType),
  taskResults: {},
  agentSteps: [],
  messageTopics: { [state.messages.length - 1]: finalIntent },
  // 缺少: flowData 清空逻辑
};
```

**`intentRouter` 不感知业务域切换，所以不会触发 `flowData` 清空。**

### P3: [`answer-synthesizer.node.ts`](apps/api/src/client/ai-customer/graph/nodes/answer-synthesizer.node.ts:107) — 不清空 flow 状态

`answerSynthesizer` 只清空 `taskResults` 和 `pendingTasks`，不清空 `flowData/flowType/flowStatus`。但它在 `intentRouter` 之后执行，所以问题不在于它——它只需要合成回答。**真正的修复点在 `intentRouter`。**

---

## 3. 解决方案

### 核心思路

在 `intentRouter` 中检测**业务域切换**（topic switch），当用户从钱包类业务切换到优惠券/订单类业务（反之亦然）时，清空 `flowData`。

### 业务域映射

定义 `FLOWTYPE_DOMAIN` 映射表，将 `FlowType` 映射到业务域：

| FlowType | 业务域 | 说明 |
|----------|--------|------|
| `WITHDRAWAL` | `wallet` | 取款 |
| `DEPOSIT` | `wallet` | 存款 |
| `BALANCE_QUERY` | `wallet` | 查余额 |
| `COUPON_QUERY` | `coupon` | 查优惠券 |
| `COUPON_CLAIM` | `coupon` | 领优惠券 |
| `ORDER_QUERY` | `order` | 查订单 |
| `POLICY` | `rag` | 政策查询 |
| `GENERAL` | `general` | 闲聊 |
| `supervised` | `supervised` | 多 Agent 协作 |

### 判断逻辑

```
currentDomain = FLOWTYPE_DOMAIN[state.flowType]  // 当前业务域
newDomain = finalIntent                            // 新 intent（wallet/coupon/order...）

if currentDomain != '' AND currentDomain != newDomain:
  → 话题切换 → 返回 flowData: {} 清空
else:
  → 同一域或首次进入 → 不处理 flowData
```

### 为什么二级 FlowType（WITHDRAWAL/BALANCE_QUERY）不需要区分？

因为 `wallet` 域内的 `WITHDRAWAL → BALANCE_QUERY` 或 `BALANCE_QUERY → WITHDRAWAL` 是**同域内细化**，不涉及跨业务上下文污染。用户在同域内说「先查余额再取款」是合理的连续对话。

| 场景 | 示例 |
|------|------|
| `WITHDRAWAL` → `wallet` | 用户说「取款 500」，Agent 从 WITHDRAWAL 进入 wallet Agent，flowData={amount:500} 被保留 |
| `BALANCE_QUERY` → `wallet` | 用户说「查余额然后取款」，Agent 从 BALANCE_QUERY 进入 wallet Agent |
| `COUPON_QUERY` → `coupon` | 用户说「查优惠券」，flowData（若有时）被保留 |
| `ORDER_QUERY` → `order` | 用户说「查订单」，flowData（若有时）被保留 |

## 5. 代码改动

### 改动 1: [`state.ts`](apps/api/src/client/ai-customer/graph/state.ts:126) — `flowData` reducer 添加空对象清空

```typescript
// 修改前（第 127-130 行）
flowData: Annotation<Record<string, any>>({
  reducer: (a: Record<string, any>, b: Record<string, any>) => ({
    ...a,
    ...b,
  }),
  default: () => ({}),
}),

// 修改后
flowData: Annotation<Record<string, any>>({
  reducer: (a: Record<string, any>, b: Record<string, any>) => {
    if (Object.keys(b).length === 0) return {};  // 空对象 = 清空（与 taskResults 一致）
    return { ...a, ...b };
  },
  default: () => ({}),
}),
```

### 改动 2: [`intent-router.node.ts`](apps/api/src/client/ai-customer/graph/nodes/intent-router.node.ts:303) — 话题切换检测

在 `intentRouter` 的单意图分支（single-word 分支）中，在 `const matchedFlowType = intentToFlowType(finalIntent);` 之后添加话题切换检测：

```typescript
// 修改前（第 303-313 行）
const matchedFlowType = intentToFlowType(finalIntent);
return {
  intent: finalIntent,
  routeCache: finalIntent,
  flowType: matchedFlowType,
  flowStatus: getInitialStatus(matchedFlowType),
  taskResults: {},
  agentSteps: [],
  messageTopics: { [state.messages.length - 1]: finalIntent },
};

// 修改后
const matchedFlowType = intentToFlowType(finalIntent);
const FLOWTYPE_DOMAIN: Record<string, string> = {
  WITHDRAWAL: 'wallet',
  DEPOSIT: 'wallet',
  BALANCE_QUERY: 'wallet',
  COUPON_QUERY: 'coupon',
  COUPON_CLAIM: 'coupon',
  ORDER_QUERY: 'order',
  POLICY: 'rag',
  GENERAL: 'general',
};
const currentDomain = state.flowType ? FLOWTYPE_DOMAIN[state.flowType] : '';
const isTopicSwitch = currentDomain !== '' && currentDomain !== finalIntent;
return {
  intent: finalIntent,
  routeCache: finalIntent,
  flowType: matchedFlowType,
  flowStatus: getInitialStatus(matchedFlowType),
  taskResults: {},
  agentSteps: [],
  // 话题切换 → 清空 flowData（空对象触发 reducer 清空逻辑）
  flowData: isTopicSwitch ? ({} as Record<string, any>) : undefined,
  messageTopics: { [state.messages.length - 1]: finalIntent },
};
```

### 改动 3（可选）: [`intent-router.node.ts`](apps/api/src/client/ai-customer/graph/nodes/intent-router.node.ts:274) — Supervised 分支也加话题切换

在 supervised JSON 分支（第 274-284 行）的 return 中，也添加 `flowData` 清空：

## 6. 风险分析

### 6.1 `flowData` reducer 改动风险

| 风险 | 等级 | 说明 |
|------|------|------|
| walletAgent 返回 `flowData: {}` | 🟢 无风险 | walletAgent 返回 `undefined`（无数据时），不是 `{}`。见 [`wallet-agent.node.ts:304`](apps/api/src/client/ai-customer/graph/nodes/wallet-agent.node.ts:304) |
| couponAgent 返回 `flowData` | 🟢 无风险 | couponAgent 不返回 `flowData`。见 [`coupon-agent.node.ts:172`](apps/api/src/client/ai-customer/graph/nodes/coupon-agent.node.ts:172) |
| orderAgent 返回 `flowData` | 🟢 无风险 | orderAgent 不返回 `flowData`。见 [`order-agent.node.ts:184`](apps/api/src/client/ai-customer/graph/nodes/order-agent.node.ts:184) |
| answerSynthesizer 返回 `flowData` | 🟢 无风险 | answerSynthesizer 不返回 `flowData`。见 [`answer-synthesizer.node.ts:107`](apps/api/src/client/ai-customer/graph/nodes/answer-synthesizer.node.ts:107) |
| rag/general 返回 `flowData` | 🟢 无风险 | rag 和 general-chat 不涉及 flowData |

### 6.2 回归场景验证

| 场景 | 预期 | 结果 |
|------|------|------|
| 取款全流程（连续 3 轮同域） | flowData 正常累积 | 🔄 reducer merge 逻辑不变 |
| 首次进入任何业务 | flowData 为空 | ⚠️ 无影响 |
| 同域内多次查询 | flowData 保留 | 🔄 `isTopicSwitch = false` |
| 跨域切换 | flowData 清空 | ✅ 新逻辑 |
| Supervisor 模式 | flowData 清空 | ✅ 可选改动 3 |

### 6.3 并发/竞争条件

- LangGraph 是单线程执行，无并发问题
- `state.flowType` 在每个 Node 执行前已确定，`intentRouter` 读到的 `state.flowType` 是上一轮的最终值

## 7. 未覆盖场景

### 同域二次操作（需要 Phase 3 Session Reset）

如果用户在同一个业务域内完成一个流程后想重新开始（例如：完成取款后再次取款），当前方案不会清空 `flowData`，因为 `isTopicSwitch = false`。

**示例：**

```
Round 1: 取款 500 → flowStatus=COMPLETED, flowData={amount:500}
Round 2: 再取款 300 → intent=wallet, 同域 → flowData 未清空
```

这个场景需要 Document 39 §4.3 定义的 `detectAndHandleSessionReset()` 逻辑——在 `answerSynthesizer` 中检测 `flowStatus === 'COMPLETED'` 且新用户输入属于同一业务域时，主动重置 flow 状态。**不在本次改动范围内。**

### filterSupervisorMessages（Phase 4，Document 39 §6.2）

`filter-messages.ts` 中的 `filterAgentMessages` 函数当前逻辑不完善（Human 消息过滤逻辑不正确），但这是独立问题，不影响本方案。

## 附录 B：决策记录

| 决策 | 选项 | 选择理由 |
|------|------|---------|
| 检测位置 | intentRouter vs answerSynthesizer | intentRouter 先执行，能最早检测话题切换。answerSynthesizer 不感知 intent |
| 清空粒度 | 全清 vs 选择性清空 | 全清 `flowData` 最安全。选择性清空需要定义保留哪些字段，复杂度高 |
| 域映射位置 | `flow-types.ts` vs `intent-router.node.ts` | `flow-types.ts` 已有 `intentToFlowType` 映射，但 `FLOWTYPE_DOMAIN` 是话题切换专用映射，放在使用处 `intent-router.node.ts` 更内聚 |
| flowData 类型 | `{}` vs `undefined` | `{}` 触发 reducer 空对象检测；`undefined` 不触发 reducer |
