## 1. 问题现象

### 1.1 用户输入

```
帮我查看今天领取的优惠券和昨天的取款记录
```

### 1.2 期望输出

同时展示优惠券领取记录 + 钱包取款记录，一条回复中包含所有数据。

### 1.3 实际输出（修复前）

```
...优惠券数据...

I'm sorry, but I can only assist with wallet-related inquiries...
```

钱包 Agent 在看到用户消息中的 "优惠券" 关键词后，主动声明"我只处理钱包相关查询"，尽管其 job 只是查询取款记录。

### 1.4 根本矛盾

用户一个问题包含两个意图 → IntentRouter 拆分为 `['wallet', 'coupon']` → Supervisor 依次调度两个 Agent → **但 Agent 的系统提示要求它们"礼貌引导用户回到自己的领域"**，导致：

1. Agent 在回复末尾添加越权声明
2. filter-messages 让所有 Agent 都看到完整的原始用户消息（含"优惠券"关键词）
3. AnswerSynthesizer 原样拼接所有 Agent 输出

---

## 2. 根因分析

三层防御同时失效：

### Layer 1: Agent Prompt（触发层）

| Agent | 修复前提示 | 问题 |
|-------|-----------|------|
| `wallet-agent` | "If the user asks about topics outside your scope... Ignore them silently — other assistants will handle those topics." | 后半句仍有歧义，LLM 不一定遵守 |
| `coupon-agent` | "If the question is not about coupons, politely guide the user back." | **主动要求 LLM 声明"不归我管"** |
| `order-agent` | "If the question is not about orders, politely guide the user back." | **同上** |

### Layer 2: Message Filter（过滤层）

文件: [`filter-messages.ts:91`](apps/api/src/client/ai-customer/graph/utils/filter-messages.ts)

```typescript
// 修复前：'supervised' 话题的消息保留给所有 Agent
if (msgTopic === 'supervised') return true; // ← 无差别保留
```

`'supervised'` 话题消息（原始复合查询）被保留给 **所有 Agent**，导致 wallet Agent 看到用户问了"优惠券"，触发其越权声明。

### Layer 3: Answer Merge（合并层）

文件: [`answer-synthesizer.node.ts`](apps/api/src/client/ai-customer/graph/nodes/answer-synthesizer.node.ts)

修复前 AnswerSynthesizer **原样拼接**所有 Agent 的 `taskResults`，不做任何内容清洗。

## 4. 修复详解

### Fix 1: wallet-agent.node.ts — Scope Restriction 强化

**位置**: [`wallet-agent.node.ts:146`](apps/api/src/client/ai-customer/graph/nodes/wallet-agent.node.ts)

**改动**: 在 `## Hard Rules` 顶部新增 CRITICAL Scope Restriction 章节：

```typescript
## Hard Rules (Violation = mistake)

### CRITICAL: Scope Restriction
- You ONLY handle wallet/KYC topics: balance, transactions, withdrawal, payment channels, KYC.
- If the user's message mentions topics outside your scope (coupons, orders, products, lucky-draw, etc.),
  ABSOLUTELY do NOT mention them. Do NOT say "this is outside my scope" or "I cannot help with that"
  or "please contact another team". Other specialized assistants will handle those parts.
- Only respond to the wallet-related part of the user's question. Ignore all non-wallet content completely.
```

同时移除了旧的行末逻辑：
```typescript
// 已删除：
// - If the user asks about topics outside your scope... Ignore them silently...
```

### Fix 2: coupon-agent.node.ts — 同上

**位置**: [`coupon-agent.node.ts:74`](apps/api/src/client/ai-customer/graph/nodes/coupon-agent.node.ts)

**改动**:
1. 在 `## Hard Rules` 中增加 Scope Restriction（coupon 领域专属）
2. 删除底部 `- If the question is not about coupons, politely guide the user back.`

### Fix 3: order-agent.node.ts — 同上

**位置**: [`order-agent.node.ts:86`](apps/api/src/client/ai-customer/graph/nodes/order-agent.node.ts)

**改动**:
1. 在 `## Hard Rules` 中增加 Scope Restriction（order 领域专属）
2. 删除底部 `- If the question is not about orders, politely guide the user back.`

### Fix 4: answer-synthesizer.node.ts — 双层过滤

**位置**: [`answer-synthesizer.node.ts:36`](apps/api/src/client/ai-customer/graph/nodes/answer-synthesizer.node.ts)

**改动 A — Prompt 层过滤**：在 `SYNTHESIZER_PROMPT` 中新增：

```typescript
## IMPORTANT: Result Filtering Rule
The query results below come from MULTIPLE specialized agents. Some agents may include
disclaimers like "this is outside my scope" or "I cannot help with that" or "please contact
another team". IGNORE those disclaimers — each agent was only given their relevant part of
the user's question. Only present the actual data and information from each agent's results.
If an agent's result only contains a disclaimer with no useful data, silently skip that
agent's output entirely.
```

**改动 B — 代码层过滤**：新增 `cleanResult()` 函数：

```typescript
const cleanResult = (text: string): string => {
  const patterns = [
    /outside\s+(my\s+)?scope/i,
    /not\s+(my\s+)?(field|responsibility|area)/i,
    /cannot\s+help\s+with\s+that/i,
    /please\s+contact\s+(another|the\s+relevant)\s+(team|department)/i,
    /i\s+(only\s+)?handle/i,
  ];
  return text
    .split('\n')
    .filter((line) => !patterns.some((p) => p.test(line)))
    .join('\n')
    .trim();
};
```

合并逻辑从 `result` 改为 `cleanResult(String(result))`。

### Fix 5: filter-messages.ts — 消息话题精准过滤

**位置**: [`filter-messages.ts:91`](apps/api/src/client/ai-customer/graph/utils/filter-messages.ts)

**改动**：

```typescript
// 修复前：所有 Agent 都看到 supervised 话题消息
if (msgTopic === 'supervised') return true;

// 修复后：只有被 pendingTasks 明确分配的 Agent 才看到
if (msgTopic === 'supervised') {
  if (!currentAgent) return true; // 向后兼容
  return pendingTasks.some(t => t.agent === currentAgent);
}
```

**为什么这样可以工作**：
- `pendingTasks` 是由 Supervisor Node 维护的任务列表，明确记录了哪些 Agent 被分配了任务
- wallet Agent 只在 `pendingTasks` 包含 `{ agent: 'wallet' }` 时才看到原始用户消息
- 即使消息中包含"优惠券"关键词，wallet Agent 看不到（因为其 pendingTask 中只标记了 wallet 任务）

修复后形成 **5-Layer Defense System**（新增 Layer 5）：

```

│                    5-Layer Defense System                                 │
├──────────────┬────────────────────────────────────┬──────────────────────┤
│ Layer        │ 机制                                │ 状态                 │
├──────────────┼────────────────────────────────────┼──────────────────────┤
│ Layer 1      │ 启动时验证工具注册                   │ ✅ 已实现            │
│ Layer 2      │ Agent 运行时工具数组检查              │ ❌ 未实现 (R01)      │
│ Layer 3      │ 集成测试                             │ ❌ 未实现            │
│ Layer 4      │ ESLint 规则                          │ ❌ 未实现            │
│ Layer 5 🔥   │ 复合意图三层防御                      │ ✅ 已实现 [本文 §4]  │
│              │  ├─ Agent Prompt Scope Restriction   │                     │
│              │  ├─ Message Topic 精准过滤            │                     │
│              │  └─ AnswerSynthesizer 内容清洗        │                     │
└──────────────┴────────────────────────────────────┴──────────────────────┘
```

### 三层防御触发链路

```
用户输入复合查询
    │
    ▼
IntentRouter 拆分子意图 → pendingTasks: [{agent:'wallet'},{agent:'coupon'}]
    │
    ▼
Supervisor 调度钱包 Agent
    │
    ▼
filter-messages（Layer 5-②）
    ├─ 检查 currentAgent = 'wallet'
    ├─ pendingTasks 包含 wallet → 保留 supervised 消息
    └─ 消息中包含"优惠券"关键词 → 但不影响，因为 wallet 只看到自己的任务
    │
    ▼
钱包 Agent 调用工具 → 返回取款记录（Layer 5-① 确保不声明"越权"）
    │
    ▼
Supervisor 调度优惠券 Agent
    │
    ▼
filter-messages
    ├─ currentAgent = 'coupon' → 保留 supervised 消息
    └─ 优惠券 Agent 调用工具 → 返回优惠券数据
    │
    ▼
AnswerSynthesizer 合并（Layer 5-③）
    ├─ cleanResult() 剥离任何 disclaimer 行
    └─ LLM 按过滤指令只呈现数据
    │
    ▼
最终回复：取款记录 + 优惠券数据，干净无越权声明
```

## 6. 开发规则

### Rule 1: Agent Prompt 中不得使用"politely guide back"

```typescript
// ❌ 禁止
"- If the question is not about [domain], politely guide the user back."

// ✅ 正确
"- You ONLY handle [domain] topics: [list]. Do NOT mention outside-scope topics."
"- Only respond to the [domain]-related part of the user's question."
```

### Rule 2: 所有 Agent 必须包含 CRITICAL Scope Restriction

Scope Restriction 必须放在 `## Hard Rules` 顶部，格式固定：

```
### CRITICAL: Scope Restriction
- You ONLY handle [domain] topics: [specific list].
- If the user's message mentions topics outside your scope ([other domains]),
  ABSOLUTELY do NOT mention them. Do NOT say "this is outside my scope" or
  "I cannot help with that" or "please contact another team".
  Other specialized assistants will handle those parts.
- Only respond to the [domain]-related part of the user's question.
  Ignore all non-[domain] content completely.
```

### Rule 3: 新增 Agent 时必须注册 Scope Restriction

新增 Agent 时 checklist：
- [ ] 已添加 Scope Restriction 到 Hard Rules
- [ ] 已确认不存在"politely guide"、"outside my scope"等措辞
- [ ] 已在 `intentToAgentMap` 或相关路由注册

### Rule 4: filter-messages 处理 supervised 话题必须按 pendingTasks 过滤

```typescript
// 任何新增的 topic 过滤逻辑都必须考虑 Agent 隔离
if (msgTopic === 'supervised') {
  if (!currentAgent) return true;
  return pendingTasks.some(t => t.agent === currentAgent);
}
```

### Rule 5: answerSynthesizer 必须包含内容清洗

合并多个 Agent 输出时，必须有代码层的内容清洗。`cleanResult()` 的 pattern 列表应随着新 Agent 的增加而更新。

### Rule 6: "politely guide the user back" 是反模式

| 场景 | 效果 |
|------|------|
| 单 Agent 用户问错了领域 | LLM 会自己判断，不需要 prompt 教它说"不归我管" |
| 多 Agent 复合查询 | **必现 Bug** — Agent 做了分内工作还要加 disclaimer |
| 用户故意跨领域 | 应由 IntentRouter 判断，而不是 Agent 拒绝 |
