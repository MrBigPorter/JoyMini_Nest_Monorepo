# 转人工友好提示需求分析

## 当前行为

当用户说"转人工"时：

```
orchestrator 检测到 human_support
  → return { transferToHuman: true, labels: [] }  // 立即返回，不跑任何 Agent
  → AiCustomerService: dispatch ai_transfer + 设置 handlerId
  → 前端收到 transfer 事件 → 切换人工模式
  → ❌ 用户看不到任何 AI 回复
```

**问题**: 用户说了"转人工"后，AI 没有说话就直接切到人工模式了。用户可能不确定系统是否收到了请求。

## 方案对比

### 方案 A: LLM 生成友好回复

```
orchestrator 检测到 human_support
  → LLM 生成: "I understand you'd like to speak with a human agent. Transferring you now..."
  → 以 ai_token/ai_done 推给前端
  → 用户看到 AI 回复后 → handlerId='awaiting_human' + ai_transfer
```

| 优点                                 | 缺点                         |
| ------------------------------------ | ---------------------------- |
| 回复自然、个性化                     | 额外 LLM 调用（成本 + 延迟） |
| 可包含上下文（如"正在为您转接客服"） | 实现复杂                     |

### 方案 B: 固定提示

```
orchestrator 检测到 human_support
  → 用固定模板: "I'm transferring you to a human agent. Please wait."
  → 以 ai_token/ai_done 推给前端
  → handlerId='awaiting_human' + ai_transfer
```

| 优点        | 缺点             |
| ----------- | ---------------- |
| 零 LLM 成本 | 回复固定、不灵活 |
| 零延迟      | 多语言需预设模板 |
| 实现简单    |                  |

### 方案 C: 继续走当前模式（不回复）

```
orchestrator 检测到 human_support
  → 直接 transfer，不回复任何消息
```

| 优点   | 缺点         |
| ------ | ------------ |
| 最简单 | 用户没有反馈 |
| 零成本 | 体验不好     |

## 建议

方案 B（固定提示）最平衡。在 orchestrator 检测到 `human_support` 时，不再直接 return，而是：

1. 生成一条固定的 AI 回复（如 "I'm transferring you to a human agent. Please wait."）
2. 这条消息通过正常的 ai_token/ai_done 推送给前端
3. 再执行 transfer 逻辑（handlerId + ai_transfer）

实现只需要在 orchestrator.node.ts 的 `human_support` 检测处改为：

```typescript
if (domainLabels.some((d) => d.label === "human_support")) {
  const transferMsg = new AIMessage(TRANSFER_MESSAGE);
  return {
    transferToHuman: true,
    labels: [],
    messages: [transferMsg],
  };
}
```
