## 1. 背景与动机

### 1.1 问题

当前 AI 客服在执行业务操作（提现、领券、抽奖、地址管理）时，流程如下：

```
用户: "提现 500 到 GCash"
  → LLM 提取参数
  → LLM 问 "确认吗？"
  → 用户: "确认"
  → LLM 调 applyWithdraw tool → 真实提现 ✅
```

**安全问题**：保护完全依赖 LLM 的 prompt 约束。prompt injection 可以绕过文字确认直接调 tool。

**体验问题**：重要的操作（资金、数据）没有直观的视觉确认，用户误触风险高。

### 1.2 目标

写操作需要两步确认：

```
LLM 提取参数 → 不调 tool → 前端卡片展示参数 + [确认] [取消] → 用户点确认 → 后端调 tool
```

### 1.3 涉及的写操作

| 操作 | 工具 | 参数 | 风险 |
|------|------|------|------|
| 提现 | `applyWithdraw` | amount, channelId, account, accountName | 🔴 资金 |
| 领券 | `claimCoupon` | couponId | 🟡 资产 |
| 兑换码 | `redeemCouponCode` | code | 🟡 资产 |
| 抽奖 | `draw` | ticketId | 🟡 消耗 |
| 删地址 | `deleteAddress` | addressId | 🟡 数据 |

## 2. 完整流程图

```
用户: "提现 500 到 GCash"
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ LangGraph 执行                                            │
│   1. intentRouter → wallet                                │
│   2. orchestrator → runStandardAgent                      │
│   3. LLM 分析 → 提取参数 {amount:500, channel:GCash, ...}  │
│   4. 不调 applyWithdraw ❌                                 │
│   5. 返回 pendingConfirm                                  │
└──────────────────────────────────────────────────────────┘
  │
  ▼
AiCustomerService.chatStream → 检测到 pendingConfirm
  │
  ├── AiActionConfirmService.generate() → confirmToken
  └── dispatch(ai_confirm) → Socket
  │
  ▼
Flutter 收到 AI_CONFIRM 事件
  ┌────────────────────────────┐
  │ 💳 提现确认                 │
  │ 金额: ₱500                 │

  │

  └── 用户点 [取消]
      → POST /api/ai/customer/confirm { confirmToken, accepted: false }
      → 后端记录日志，不执行
```

## 3. Socket 事件定义

在 `packages/shared/src/im/constants.ts` 新增：

```typescript
// Server → Client: 需要用户确认
AI_CONFIRM: "ai_confirm",

// Client → Server: 用户确认/取消
AI_CONFIRM_RESPONSE: "ai_confirm_response",

// Server → Client: 操作执行结果
AI_ACTION_RESULT: "ai_action_result",
```

### AI_CONFIRM 事件 payload

```typescript
{
  conversationId: string;
  action: string;           // 'withdraw' | 'claim_coupon' | 'redeem_code' | 'draw' | 'delete_address'
  summary: {                // 卡片展示信息
    title: string;          // "提现确认"
    amount?: string;
    channel?: string;
    fee?: string;
    account?: string;       // 脱敏显示
    fields?: Array<{ label: string; value: string }>;  // 通用键值对
  };
  confirmToken: string;     // 一次性 token
  expiresAt: number;        // 过期时间戳 (ms)
}
```

### AI_ACTION_RESULT 事件 payload

```typescript
{
  conversationId: string;
  success: boolean;
  message?: string;
  data?: any;
}
```

## 4. AiActionConfirmService 设计

**文件**: `apps/api/src/client/ai-customer/ai-action-confirm.service.ts`

### 接口

```typescript
interface ConfirmPayload {
  action: string;           // 'withdraw' | 'claim_coupon' | ...
  params: Record<string, any>;  // 执行参数
  summary: Record<string, any>; // 展示信息
  userId: string;           // 绑定的用户
}
```

### 方法

```typescript
class AiActionConfirmService {
  // 生成 confirmToken，存入 Redis
  // key: `ai:confirm:${token}` (UUID), value: JSON.stringify(ConfirmPayload)
  // TTL: 60s
  async generate(userId: string, action: string, params: object, summary: object): Promise<{
    token: string;
    expiresAt: number;
  }>;

  // 验证并消费 token
  // 返回 null 表示 token 无效/已过期
  async consume(token: string, userId: string): Promise<ConfirmPayload | null>;
}
```

### 安全设计

| 风险 | 防护 |
|------|------|
| Token 猜测 | UUID v4 不可猜 |
| 过期 token | 60s TTL |
| 重复消费 | 消费后 Redis 删除 |
| 跨用户 | consume 时校验 userId |
| 参数篡改 | 参数在 generate 时锁定到 Redis，不依赖前端 |

## 5. orchestrator.node.ts 修改方案

### 5.1 写操作标记

在 orchestrator 的 AGENT_MAP 或 tool 注册时，声明哪些 tool 需要确认。

不需要改现有 tool 函数本身。在 orchestrator 的 agent 循环中，通过检查 agent 执行的 tool name 来判断。

实现方式：在 `orchestrator.node.ts` 顶部定义需要确认的 tool 名列表：

```typescript
const CONFIRM_REQUIRED_TOOLS = new Set([
  'applyWithdraw',
  'claimCoupon',
  'redeemCouponCode',
  'draw',
  'deleteAddress',
]);
```

### 5.2 Agent 循环修改

当前流程：

```
for (label of executionOrder) {
  result = await runStandardAgent({ ... })
  pushAgentResult(label, result, ...)
}
```

改为：

```
let pendingConfirm = null;

for (label of executionOrder) {
  result = await runStandardAgent({ ... })

  // 检测 agent 是否调用了写操作工具
  const writeToolCalls = result.toolCalls?.filter(
    tc => CONFIRM_REQUIRED_TOOLS.has(tc.name)
  );

  if (writeToolCalls?.length > 0) {
    // 截取参数，不执行
    pendingConfirm = {
      action: mapToolToAction(writeToolCalls[0].name),
      params: writeToolCalls[0].args,
      summary: buildSummary(writeToolCalls[0]),
    };
    break; // 停止执行后续 agent
  }

  pushAgentResult(label, result, ...)
}
```

### 5.3 orchestrator 返回值

在 `AgentState` 加新字段 `pendingConfirm`：

```typescript
pendingConfirm: Annotation<{
  action: string;
  params: Record<string, any>;
  summary: Record<string, any>;
} | null>({
  reducer: (a, b) => b ?? a,
  default: () => null,
}),
```

orchestrator 检测到写操作时：

```typescript
return {
  messages: [...state.messages, new AIMessage(confirmPromptText)],
  pendingConfirm,
  labels: [],
};
```

其中 `confirmPromptText` 是 AI 的询问文案，例如 "I'll help you withdraw ₱500 to GCash. Please confirm the details below."

### 5.4 注意

- 如果 agent 只做了查询（read），流程不变
- 如果 agent 调了多个写操作，只拦截第一个
- `pendingConfirm` 非 null 时，后续 agent 不执行

## 6. ai-customer.service.ts 修改

### 6.1 chatStream 方法

在 graph 执行完后，`transferToHuman` 检查之后，加 `pendingConfirm` 检查：

```typescript
// 现有：转人工检查
if (finalState?.values?.transferToHuman && callbacks.onTransfer) {
  // ...（已有逻辑）
}
// 新增：确认卡片检查
else if (finalState?.values?.pendingConfirm) {
  const pc = finalState.values.pendingConfirm;
  const { token, expiresAt } = await aiActionConfirmService.generate(
    userId, pc.action, pc.params, pc.summary,
  );

  // Socket 推送
  if (conversationId) {
    eventsGateway.dispatch(conversationId, SocketEvents.AI_CONFIRM, {
      conversationId,
      action: pc.action,
      summary: pc.summary,
      confirmToken: token,
      expiresAt,
    });
  }

  // SSE 推送
  callbacks.onConfirm?.({
    action: pc.action,
    summary: pc.summary,
    confirmToken: token,
    expiresAt,
  });
}
```

### 6.2 全 Socket 通道（无 SSE）

全走 Socket，不需要扩展 callback 接口。`AiMessageListener` 收到 `AI_CONFIRM` 事件后由 `eventsGateway.dispatch` 直接推给 Flutter。

不需要改 `testChat`（测试路径不走确认流程）。

### 6.3 关于 OTP 提现流程

当前 `wallet-prompt.ts` 中的 OTP 提现流程：

```
用户确认提现 → LLM 调 requestWithdrawOtp → 用户输 OTP → verifyWithdrawOtp → applyWithdraw
```

卡片方案是截断这个流程，LLM 提取参数后直接返回确认，不调 tool。这意味着 **OTP 验证在卡片流程中被跳过**。

处理方式：

1. `applyWithdraw` 内部已经有 KYC + 余额 + 防重放检查（wallet-tools.ts:443）
2. 卡片确认 + 调已有 API `POST /wallet/withdraw/apply` 代替了 LLM 驱动的 OTP 流程
3. 如果需要 OTP，可以在 `POST /wallet/withdraw/apply` 前要求前端先验 OTP（服务端已支持 OTP 验证）
4. **本轮先跳过 OTP**（卡片确认替代 LLM 文字确认已经是升级），后续迭代再加 OTP

## 7. 执行方式：直接调现有客户端 API

Flutter 点确认后，**不新写 API**，直接调现有的客户端接口：

| 操作 | 调用的 API |
|------|-----------|
| 提现 | `POST /wallet/withdraw/apply` |
| 领券 | `POST /coupon/claim` |
| 兑换码 | `POST /coupon/redeem` |
| 抽奖 | `POST /lucky-draw/draw` |
| 删地址 | `DELETE /address/:id` |

confirmToken 只用于前端 60s 过期判定（按钮置灰），不参与后端安全拦截。接口安全由 JWT + 现有服务端校验保障。

### 8.3 状态穷举（所有卡片通用）

| 状态 | 表现 | 处理 |
|------|------|------|
| ✅ **操作成功** | API 返回成功 → 关闭卡片 → 显示操作结果消息 | 发 `AI_ACTION_RESULT` 事件 |
| 🔴 **API 返回业务错误** | 余额不足 / KYC 未过 / 券已领完 | 卡片下方显示红色错误提示，保留按钮 |
| 🔴 **网络失败** | 点确认后 timeout / 无响应 | 按钮 loading → 超时 → 提示"网络异常，请重试" |
| 🟡 **余额不足**（提现） | API 返回余额不足 | 卡片显示"余额不足，无法提现" |
| 🟡 **KYC 未完成**（提现） | API 返回 KYC 未通过 | 卡片显示"请先完成 KYC 认证" |
| 🟡 **券已领完**（领券） | API 返回库存不足 | 卡片显示"优惠券已领完" |
| 🟡 **重复点击** | 用户快速连点两次确认 | 点确认后按钮 loading + disabled |
| 🟡 **卡片过期** | 60s 超时 | 按钮置灰，显示"已过期，请让 AI 重新发起" |
| 🔵 **加载中** | 点确认后按钮变 spinner | 防重复提交 |
| ⚠️ **切后台返回** | token 可能已过期 | 检查剩余时间，过期则提示 |
| 🟣 **中英文** | 卡片文字自动适配语言 | 用 App 当前语言 |
| ⚪ **操作被拒**（删地址） | 地址已被删除 | 卡片提示"地址已不存在" |

### 8.4 额外边界场景

| # | 场景 | 问题 | 处理 |
|---|------|------|------|
| 1 | **Token 先流出，卡片后出现** | orchestrator 会先流一段 AI 文字（"I'll help you withdraw..."），然后卡片才出现。用户看到文字 + 卡片同一件事，体验割裂 | 让 orchestrator 检测到 pendingConfirm 时**不返回 AIMessage**（messages 不加内容），只发 `pendingConfirm`。前端收到后直接渲染卡片，不显示 AI 文字 |
| 2 | **用户发新消息** | 卡片还在，用户又发了新消息 | 旧卡片自动关闭，`confirmToken` 作废（60s 后过期）。用户新消息触发新一轮流程 |
| 3 | **Socket 重连** | 卡片状态丢失 | 不恢复。token 60s 后自动过期，用户重新问 AI |
| 4 | **关闭聊天页面** | 卡片消失 | 同 3，token 自动过期 |
| 5 | **两个写操作同时触发** | user+wallet 都调了写操作 | 目前设计只拦截第一个写操作 tool，后面的 agent 不执行（break），一张卡 |
| 6 | **用户取消后** | 点了取消，聊天里没有记录 | Flutter 在聊天中插入一条系统消息："❌ 已取消提现 ₱500" |
| 7 | **用户确认后** | 操作成功，聊天里怎么显示 | 显示结果消息："✅ 提现 ₱500 成功，预计 1-3 个工作日到账" |
| 8 | **抽奖即开型** | 抽奖是即时出结果的操作 | 抽奖卡片确认后直接调 API，返回里带奖品信息，卡片显示"🎉 恭喜中奖！"或"😅 未中奖" |

### 8.5 AI_ACTION_RESULT 事件

操作执行完后，后端/Flutter 发 `AI_ACTION_RESULT` 事件：

```typescript
{
  conversationId: string;
  action: string;     // 'withdraw' | 'claim_coupon' | ...
  success: boolean;
  message: string;    // 友好提示
  data?: {
    amount?: number;
    balance?: number;
    prize?: string;
    // 各操作独特数据
  };
}
```

Flutter 收到后：
- 成功：关闭卡片，在聊天中显示一条操作结果消息
- 失败：卡片显示错误信息，保留重试按钮

### 9.2 数据模型

`ai_action_model.dart`：

```dart
// 确认卡片数据（从 AI_CONFIRM 事件解析）
class AiConfirmData {
  final String action;        // 'withdraw' | 'claim_coupon' | ...
  final Map<String, dynamic> summary;  // 展示字段
  final String confirmToken;
  final int expiresAt;        // 过期时间戳 (ms)
}

// 操作结果数据（从 AI_ACTION_RESULT 事件解析）
class AiActionResult {
  final String action;
  final bool success;
  final String message;
  final Map<String, dynamic>? data;
}

// 卡片生命周期状态
enum ConfirmCardStatus {
  pending,    // 等待用户操作
  expired,    // 已过期
  loading,    // 确认中（调 API 中）
  success,    // 操作成功
  failed,     // 操作失败
  cancelled,  // 用户取消
}
```

### 9.3 ViewModel 状态管理

在 `ChatViewModel`（`ChatListState`）中加状态：

```dart
class ChatListState {
  // ...现有字段
  
  // 新增
  final AiConfirmData? confirmData;
  final ConfirmCardStatus confirmStatus;
  final String? confirmErrorMessage;
}
```

方法：

```dart
// 收到 AI_CONFIRM 事件时调用
void setConfirm(AiConfirmData data) {
  state = state.copyWith(
    confirmData: data,
    confirmStatus: ConfirmCardStatus.pending,
  );
  // 启动 60s 倒计时
  _startConfirmTimer(data.expiresAt);
}

// 用户点确认时调用
void confirmAction() async {
  state = state.copyWith(confirmStatus: ConfirmCardStatus.loading);
  try {
    final result = await _apiService.call(state.confirmData!.action, ...);
    state = state.copyWith(
      confirmStatus: ConfirmCardStatus.success,
      confirmData: null,  // 关闭卡片
    );
    // 在聊天中插入结果消息
    _addResultMessage(result);
  } catch (e) {
    state = state.copyWith(
      confirmStatus: ConfirmCardStatus.failed,
      confirmErrorMessage: e.toString(),
    );
  }
}

// 用户点取消时调用
void cancelConfirm() {
  state = state.copyWith(
    confirmStatus: ConfirmCardStatus.cancelled,
    confirmData: null,
  );
  // 插入取消消息
  _addCancelMessage();
}
```

```dart
    final data = Map<String, dynamic>.from(data);
    vmNotifier.setConfirm(AiConfirmData(
      action: data['action'],
      summary: data['summary'],
      confirmToken: data['confirmToken'],
      expiresAt: data['expiresAt'],
    ));
    break;
    
  case SocketEvents.aiActionResult:
    // 操作执行结果（如果用户通过 API 确认，结果已由 API 返回）
    // 如果其他设备确认了，这里会收到广播
    vmNotifier.setConfirm(null); // 关闭卡片
    break;
}
```

### 9.6 卡片生命周期

```
时间线:
0s     AI_CONFIRM 事件到达 → 渲染卡片（pending）
       ↓
用户点 [确认]           → loading → 调 API → 成功/失败
       ↓                        或
60s 未操作              → expired → 按钮置灰
       ↓                        或
用户发新消息 / 关闭页面  → 卡片消失（不通知后端）
       ↓
用户点 [取消]           → cancelled → 插入取消消息
```

## 11. 验证

### 后端

1. `confirmToken` 生成 → 存入 Redis → 返回 token
2. `consume` 有效 token → 返回参数
3. `consume` 无效/过期 token → 返回 null
4. `consume` 两次相同的 token → 第二次返回 null
5. TypeScript 编译 0 error

### 集成

1. 发"提现 500" → 收到 `AI_CONFIRM` 事件，不调 tool
2. 点确认 → API 调 `applyWithdraw` 执行成功
3. 点取消 → 不执行，返回取消消息
4. 等 60s 再点确认 → 提示"已过期"
