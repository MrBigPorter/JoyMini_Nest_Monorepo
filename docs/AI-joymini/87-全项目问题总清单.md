## D. 本次新发现 · N（6 条）

> 2026-11-11 实测发现，不在 #85 台账内。

| ID | 问题 | 证据 | 后果 |
|:--:|---|---|---|
| **N-1** | **知识库全量未导入本地**：源文档 27 篇 / 311 chunk，本地库只有 2 篇测试文档 / 14 chunk | `docker exec lucky-db psql -c "select count(*) from knowledge_documents"` → 2 | 本地 RAG 只能查到测试数据，效果无法验证 |
| **N-2** | **Meilisearch 在生产环境不存在**：`compose.prod.yml` 无 `meilisearch` 服务，`deploy/.env.prod` 无 `MEILISEARCH_URL`，代码回落到默认值 `http://joymini-meilisearch:7700` → 解析失败 → `client = null` → **第 2 层 BM25 静默禁用**。本地有容器 `joymini-meilisearch`，但当前已停机 | `compose.prod.yml` 服务列表、`deploy/.env.prod`、`meilisearch.service.ts:82-84`、`onModuleInit` 降级逻辑 | 生产 4 层检索实际只有 3 层，且仅一行 warning，无指标、无告警 |
| **N-3** | **导入链路无完成校验**：`process_status` 字段存在，但没有用例或告警校验"文档是否真的入库可检索" | `knowledge_documents.process_status` | 无法区分"切分完成"和"已入库可检索" |
| **N-4** | **25 个文件未提交，无基线** | `git status --short \| wc -l` → 25 | 改坏了无法回滚；无法追溯"昨天是什么样" |
| **N-5** | **本地与生产数据完全分离**：数据源不同、组件不同、知识库不同 | 上述 N-1 / N-2 | 线上问题无法在本地复现 |
| **N-6** | **向量化失败被静默吞掉**：单 chunk embedding 失败只记 warn，任务照常 completed，文档状态无条件置 `indexed`；重传时也不重置状态。修复方向：失败抛异常交给 BullMQ 退避重试（重试只补 `embedding IS NULL` 的 chunk）；`failCount > 0` 不置 `indexed`；重传切片后置 `chunked` | `rag-embedding.processor.ts:104-128`、`rag-sync.service.ts:493-512`；2026-11-11 重传后 27 篇全 `indexed`，实际 302 个 chunk 缺 9 个（contact-support 6、platform-rules 3），`verify-knowledge` 检出 | 缺失 chunk 永远检索不到；后台显示全绿、无告警；只能靠人工校验发现 |
