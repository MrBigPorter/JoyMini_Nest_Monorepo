## 2. 学习与求职准备（三件事）

### 2.1 把链路讲到脱稿

材料：[#91 一条消息的旅程](./91-一条消息的旅程.html)

**只背主干 7 框**，其余两张图理解即可：

```
① 入口      POST / socket → 用户消息落库广播 → 判断要不要叫 AI
② 监听器    AI_MESSAGE_REQUESTED → 造 traceId → chatStream
③ 准备      找 thread · 查成员 · 记长度 · 推 thinking
④ 图里      打意图标签 → 先判转人工 → 再决定调不调 agent
⑤ 取增量    读 finalState → 切出本轮新增的消息
⑥ 三路      转人工 / 确认卡片 / 正常（互斥）
⑦ 广播      落库(role=assistant) → 会话房间 + 私房 → .except 去重
```

验收标准：**合上页面能画出来，并且在每个框旁写一句"这里失败会怎样"**。

配套三条读法（来自 #91）：

1. 先找出口，再读入口 —— 先数 `return`，再倒着读
2. 每一行先问：这是**承诺**还是**装饰**（失败必须报错 vs warn 即可）
3. 状态只在两处：图内 `AgentState`，图外 `Conversation` 表 + Redis

### 2.2 三个 bug 故事（STAR，重点是第四段"验证"）

JD / 面试官真正要的是"用数据验证改动"，不是"我写了多少代码"。

| # | 故事 | 判断点 | 验证方式 |
|:--:|---|---|---|
| 1 | **转人工永远不触发** | 检测放在 `labels.length===0` 和 MIN_SCORE 两条 fallback 之后；短句意图分天然低 → 永远走闲聊 | `orchestrator.node.spec.ts` 空 labels 用例 + E2E 明确转人工 PASS |
| 2 | **部分客户端收不到 AI 回复** | 只推会话房间，未 `join_chat` 的客户端收不到 | 双通道 + `.except()`；`[DispatchFallback] private rooms: 2` |
| 3 | **"垃圾袋"被判成骂人** | 中文无词边界，`includes('垃圾')` 命中商品名 | `transfer-detector.spec.ts` 商品词用例 + 真骂人仍转 |

补充可选故事（资金/并发方向，来自 #86 §7.1）：提现冻结余额不释放、中文打进 RAG 关键词层全废。

### 2.4 定位话术（重要）

不要投"前端工程师"。用这句话：

> 「我是前端出身，但完整交付过一个含 LLM 的异步系统：IM 消息 → 事件总线 → LangGraph → 工具调用 → 双通道推送，并且能解释每一层为什么这么设计。」

对应三类岗位：AI 应用工程师、全栈、正在做 AI 功能的前端团队。

## 3. 业务现状盘点（2026-11-12）

### 3.1 已经闭环的部分

- 意图识别（pgvector + BM25 + LLM fallback，9 类）
- 多 agent + 35 个业务工具（订单 / 优惠券 / 钱包 / 地址 / KYC）
- 4 层 RAG 降级 + rerank + 知识库版本化 prompt
- 确认卡片（`AI_CONFIRM` + OTP）—— 但有三洞，见 T1-2
- 转人工：`handlerId='awaiting_human'` + admin 控制台可切换 AI/人工
- 可观测：traceId + 8 类事件（T0-2 已完成）

### 3.2 没闭环的部分（按业务影响排序）

| # | 缺口 | 现在会怎样 | 对应任务 |
|:--:|---|---|---|
| G1 | **转人工后没有"待接入"信号** | admin 只能盯列表；无通知、无队列排序，用户可能一直等 | T2-1（工单 + 消费者，需补 admin 端） |
| G2 | **handler 超时是"懒回收"** | 只有用户再发消息才触发 10 分钟判断；用户不说话就永久挂在 `awaiting_human` | T2-1 / 新增定时任务 |
| G3 | **没有任何准确率基线** | 改了好不好全靠感觉；面试无法给数字 | T0-3（golden set + 回放） |
| G4 | **中文问题走不通 RAG Layer 2** | 中文关键词检索层实际失效，只剩向量兜底 | T2-3 |
| G5 | **确认卡片三洞**（✅ 2026-11-12 已修） | 已改为 peek→verify→pop、TTL 对齐 330s、DTO 真校验 | T1-2 |
| G6 | **生产不可用的 OTP** | 不发短信、明文日志 | T1-1 |

> G1+G2 = 转人工链路只走了一半：AI 能交出去，但没人被叫来。
> G3 = 所有后续改动的"证明"都建立在它上面。
