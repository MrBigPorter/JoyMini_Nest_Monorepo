# 📋 博客前端接口对接实施计划

## 🎯 核心架构原则

> **✅ 渐进式对接，保持Mock数据并行，随时可回退**
> 每个接口对接完成后同时保留Mock数据开关，确保开发过程中不会阻塞

---

## 🔥 架构核心: 多模式适配层 (必须第一个实现)

这是整个系统最核心的部分，也是所有其他工作的地基。**在没有完成这个适配层之前，不允许对接任何业务接口。**

### ✅ 双端请求策略

| 运行环境               | 请求方式       | 网络路径                 | 缓存策略                         |
| ---------------------- | -------------- | ------------------------ | -------------------------------- |
| ✅ **服务端渲染(SSR)** | 内部gRPC调用   | 不走公网，直接服务间调用 | Redis + CDN 5-15分钟             |
| ✅ **静态生成(SSG)**   | 公网HTTP请求   | 构建时预取数据           | 静态HTML，直到下一次部署         |
| ✅ **客户端渲染(CSR)** | 浏览器HTTP请求 | 正常前端请求             | React Query / LocalStorage 5分钟 |

### ✅ 设计目标

✅ **所有三种模式使用完全相同的业务代码**
✅ 业务开发者完全不需要关心代码运行在什么环境
✅ 写操作接口自动跳过服务端执行
✅ 缓存策略自动适配当前运行环境
✅ 错误降级自动适配环境

## 💡 接口分层规则

1. **只读接口**：默认支持所有三种渲染模式
2. **写操作接口**：永远只在客户端执行，服务端自动跳过
3. **状态相关接口**：SSR下携带Cookie，客户端自动携带Token
4. **缓存时间**：根据接口类型自动设置，业务代码不需要手动配置
