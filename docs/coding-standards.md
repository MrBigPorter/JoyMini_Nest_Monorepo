# JoyMini 代码规范 — 写代码前必读

企业级 7 维度检查清单。每次写代码前，逐条对照。

## 写代码前问自己 7 个问题

### 1. 边界 — "会不会崩？"

| 检查项 | 说明 | 例 |
|--------|------|----|
| 空值/空字符串 | 参数为 `null`、`undefined`、`''` 时会不会报错？ | `if (!message) return 400` |
| 类型不对 | 传了数字当字符串怎么办？ | DTO validation |
| 数组空 | `forEach` 空数组会不会崩？ | 不会，但结果要对 |
| 对象缺字段 | `obj.field` 但 field 不存在？ | 可选链 `?.` 或默认值 |
| 并发 | 同一用户连发两条会怎样？ | 限流、队列 |
| 超时 | 外部 API 3 分钟不返回？ | `AbortController` + 超时时间 |
| 资源泄漏 | 连接用完关不关？ | `try/finally` 确保释放 |

### 2. 测试 — "怎么证明它对了？"

| 检查项 | 说明 |
|--------|------|
| 手动测试 | curl / Swagger 能调到吗？ |
| 正常路径 | 输入正常值，输出对不对？ |
| 异常路径 | 输入空值/错误值，报错对不对？ |
| 边界值 | 阈值刚好等于 0.15 时走哪个分支？ |
| 幂等性 | 调两次结果一样吗？ |

### 3. 体验 — "用户觉得怎么样？"

| 检查项 | 说明 |
|--------|------|
| 响应速度 | 用户要等多久？能不能流式？ |
| 错误提示 | 报错信息用户看得懂吗？ |
| 反馈明确 | 用户知道"正在处理"还是"已完成"吗？ |
| 一致性 | 跟其他接口返回格式一样吗？ |

### 4. 性能 — "扛得住吗？"

| 检查项 | 说明 |
|--------|------|
| 延迟 | 这个操作要多久？能不能优化？ |
| 并发 | 100 人同时调用会不会崩？ |
| 资源 | 内存、CPU、数据库连接够不够？ |
| 缓存 | 同样的结果能不能复用？ |

### 5. 维护性 — "3 个月后还能看懂吗？"

| 检查项 | 说明 |
|--------|------|
| 命名清晰 | 变量名、函数名一看就懂 |
| 注释到位 | 为什么这么写（不是写了什么） |
| 单一职责 | 一个函数只做一件事 |
| 配置分离 | 硬编码的魔术数字要命名常量 |
| 日志完整 | 出问题能根据日志定位 |

### 7. 安全性 — "会不会出事？"

| 检查项 | 说明 | 例 |
|--------|------|----|
| 注入攻击 | 参数里带 SQL 脚本、HTML 标签？ | 参数校验 + ORM 参数化查询 |
| 权限校验 | 用户 A 能查用户 B 的数据吗？ | 必须传 userId，从 token 取 |
| 敏感数据 | 返回的 JSON 有没有不该返回的字段？ | 删掉密码、手机号、token |
| 越权操作 | 普通用户能调管理员接口吗？ | Guard 检查角色 |

### 8. 可观测性 — "出问题能查到吗？"

| 检查项 | 说明 | 例 |
|--------|------|----|
| 日志完整 | 关键路径有日志吗？ | 进函数打参数，出函数打结果 |
| 链路追踪 | 一条请求跨多个服务能串联吗？ | traceId 透传 |
| 监控指标 | 接口调用量、错误率有统计吗？ | Prometheus 指标 |
| 告警 | 错误率突增有人知道吗？ | 错误率 > 1% 告警 |
| 健康检查 | 服务活着吗？ | /health 端点 |

### 9. 可用性/容错 — "挂了怎么办？"

| 检查项 | 说明 | 例 |
|--------|------|----|
| 降级 | 依赖挂了，核心功能还能用吗？ | 缓存降级、默认值返回 |
| 熔断 | 第三方 API 一直超时，别再调了 | 熔断器模式 |
| 限流 | 流量突增，保护后端 | 令牌桶、漏桶 |
| 超时控制 | 外部调用等多久？ | 所有 HTTP/DB 查询设超时 |
| 优雅关闭 | 进程退出时正在处理的请求怎么办？ | 等待进行中的请求完成 |

### 10. 模块化 — "能不能复用？"

| 检查项 | 说明 |
|--------|------|
| 关注点分离 | Controller 只处理 I/O，Service 只处理业务 |
| 依赖注入 | 不要 new，用 NestJS DI |
| 接口契约 | 函数参数和返回值类型明确 |
| 解耦 | 改 A 模块不需要改 B 模块 |

## 每次写代码的流程

```
Step 0: 想清楚再写
   └─ 这个函数要处理哪些边界情况？
   └─ 怎么验证它对了？
   
Step 1: 定义函数签名
   └─ 输入参数是什么？输出是什么？
   └─ 异常怎么返回？

Step 2: 写主体逻辑
   └─ 先处理边界情况（early return）
   └─ 再写正常逻辑

Step 3: 加日志
   └─ 进函数时打印参数
   └─ 出函数时打印结果
   └─ 异常时打印错误

Step 4: 测试
   └─ curl/Swagger 调一下
   └─ 正常输入通不通？
   └─ 异常输入崩不崩？

Step 5: 复盘
   └─ 这次学到了什么？
   └─ 下次哪里可以做得更好？
```
