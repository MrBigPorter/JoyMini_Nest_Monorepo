# 语言零闪烁最终架构 v2.0 ✅

> **最终稳定版**：经过长达3个月迭代的最终完美方案，彻底解决所有语言同步、闪烁、时序问题

---

## 🎯 核心设计原则

### 唯一真理原则

✅ **整个系统只有一个语言检测数据源** `detectLocale()`
✅ **所有模块必须统一使用这个函数，禁止任何重复实现**

### 优先级设计 (终极正确)

| 优先级 | 数据源                | 说明                     |
| ------ | --------------------- | ------------------------ |
| 🔝 1   | NEXT_LOCALE Cookie    | 用户明确意图，最高优先级 |
| 2      | URL路径               | 呈现层状态               |
| 3      | 浏览器Accept-Language | 首次访问检测             |
| 4      | 默认语言              | 兜底                     |

## 🔧 修复的历史问题

| 问题                              | 根因                    | 修复                           |
| --------------------------------- | ----------------------- | ------------------------------ |
| API请求语言错误                   | http.ts独立实现错误逻辑 | 统一使用detectLocale()         |
| Cookie设置后路径还是旧语言        | 路径优先级 > Cookie     | 调整优先级：Cookie > 路径      |
| 接口是英文但静态文本是中文        | next-intl和路由绑定     | I18nProvider主动同步路由       |
| 路由异步跳转时序BUG               | router.push是异步操作   | 检测不一致立即replace          |
| SSR/CSR水合不匹配                 | 两套逻辑不一致          | 统一检测逻辑                   |
| 构建错误: isSupportedLocale不存在 | 函数重构后未更新导入    | 使用LOCALES.includes()原生检查 |

## ✅ 最终行为保证

语言切换时序：

1.  用户点击切换语言按钮
2.  ✅ **立即设置NEXT_LOCALE Cookie**
3.  ✅ **所有后续API请求立即使用新语言**
4.  ✅ **所有静态翻译文本立即更新**
5.  ✅ **I18nProvider发现不一致立即同步路由**
6.  ✅ **整个过程零闪烁、零延迟、零不一致**

## 📝 代码实现规范

### 🔴 绝对禁止

- ❌ 禁止在任何地方重复实现语言检测逻辑
- ❌ 禁止直接读取window.location判断语言
- ❌ 禁止硬编码默认语言
- ❌ 禁止依赖localStorage存储语言状态
- ❌ 禁止导入不存在的导出函数

### ⚠ 特殊例外

> ✅ 唯一例外：`src/app/page.tsx` 根页面
>
> 根页面是Next.js 15中唯一一个**不能**使用`detectLocale()`的地方，因为在根路由上下文还没初始化完成。
>
> 根页面必须手动实现最小化检测逻辑，直接使用`LOCALES.includes()`进行验证。
>
> 这是整个系统中唯一允许的例外情况。

### 🟢 正确做法

- ✅ 所有语言检测必须调用 `detectLocale()`
- ✅ 语言状态唯一存储在 `NEXT_LOCALE` Cookie
- ✅ 优先级永远是 Cookie > 路径
- ✅ I18nProvider负责同步路由状态
