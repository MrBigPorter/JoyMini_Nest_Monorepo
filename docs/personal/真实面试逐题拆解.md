## 0. 这份记录最值钱的地方

不在后面的答案里，在**前 17 题**.

前 17 题里没有一道是技术题。这是一段**叙事审计**：面试官用十一问把候选人的履历钉死，最后一句话是面试官自己替候选人总结的。

技术题从第 18 题才开始。**也就是说：答不上 1-17，后面 18 题根本没机会答。**

## 1. 前 17 题的拆穿链条

| # | 面试官原话 | 在做什么 |
|:--:|---|---|
| 1 | 先做个自我介绍 | 让你自己先立靶 |
| 2 | 你是 19 年毕业的，工作履历说一下，**简历上写了几家公司？三家是吧？** | 让你确认。他自己已经把简历读过了，问这句是逼你背书 |
| 3 | 第一家什么岗位、什么技术？第二家、第三家也简短说一下 | 横向对比，找不一致 |
| 4 | 第一家和第二家用到的**前端技术**再说一下？ | 细节压力测试——真做过的人能说出版本、构建、踩过的坑 |
| 5 | **其他项目组用的什么技术？其他项目组不是你吗？** | ⚠️ **矛盾探测器**。你讲了自己没参与的项目 |
| 6 | 你现在最后一家是做 AI agent 开发的是吧？ | 把结论钉住，等你后面自证 |
| 7 | 你现在在职还是离职？ | 让候选人自己承认空窗 |
| 8 | 几月份离职的？ | 锁定时间点 |
| 9 | 从 4 月到现在一直没有找到合适的机会是吧？ | 把空窗期变成一条事实 |
| 10 | 简历上 8 月份之后写的几个项目都是**离职之后做的**是吧？ | 把项目与雇主剥离 |
| 11 | 这些项目上线了吗？**是去公司做支持还是在家做远程支持？** | ⚠️ 二选一陷阱。选哪个都等于"无雇主" |
| 12 | **也就是你现在写的所有 agent 相关的都是离职之后自学的？** | 面试官自己下结论。到此闭环 |
| 13 | 2026 年 4 月之前的工作流编排，用到了哪些 agent 技术？ | 开始技术面 |
| 14 | 你在最后一家公司 AI 相关的工作接触了几个月？ | 量化在职 AI 经验 |
| 15 | 工作流编排平台里你主要负责什么？ | 职责边界 |
| 16 | **大部分还是传统 RAG 检索，你说的搭架构、react 还是前端，那 RAG 里 AI 智能体设计体现在哪方面？** | ⚠️ **核心验伪题**：是 Agent，还是 RAG 套个 Agent 的壳 |
| 17 | 你的前端 React 你觉得是高级还是中级？Vue 呢？ | 对标自评，看敢不敢定级 |

### 这条链的结构

```
Q2  确认履历 → Q3-5 找矛盾 → Q6-12 连续封闭追问 7 步
                              ↓
                    "所有 agent 相关都是离职后自学的？"
                              ↓
                        叙事崩塌
```

**十一问，全是封闭式。** 面试官不问"你做了什么"，只问"是不是"，让候选人自己一句一句把结论交出去。

## 2. 为什么这套追问会成立

因为它只在**一种情况**下成立：你声称了一段无法核实的雇佣关系。

三种开场，对应三种完全不同的面试：

| 开场 | 面试官的反应 | 走向 |
|---|---|---|
| A. 「我在 X 公司负责 AI 客服」 | 空窗期 + 项目时间 → 追问链启动 | 1-12 题，风险全在这里 |
| B. 「我是独立开发者，自己做了产品」 | 没有链条可追 | 直接进 13 题技术区 |
| C. 含糊其辞「我在做 AI 相关」 | 追问更狠 | 最差 |

**关键认知：B 不是退而求其次，B 是你唯一真实且最强的版本。**

你有：一个完整仓库、一套生产化审计清单、真实资金业务链路、8 个域 Agent、35 个工具、4 层 RAG。这些东西**本来就不是一个普通在职员工做得出来的**——它们恰好是"一个人独立做产品"的证据。

用 A 讲，这些证据是在**自证**（越说越像编的）；用 B 讲，这些证据是**作品**（越说越可信）。

## 3. 两条路，选一条，别混

> ⚠️ 混着讲是最坏的结果：既没有雇主背书，又留下了追问链。

### 路线 A：保留公司叙事

- **前提**：至少有一条**能背调**的真实雇佣关系
- **代价**：必须能回答"公司还在用吗""能不能联系同事""Git 提交记录在哪"
- **风险**：Q11 二选一陷阱，Q12 被面试官总结
- **建议**：如果做不到完整可核实，不要走这条

### 路线 B：独立开发者（推荐）

- **口径一句话**：「这两年我在做自己的产品，JoyMini 是我一个人从后端到 Flutter 全栈写的，按生产标准做的，代码在这。」
- **1-12 题全部失效**：没有三家、没有空窗期解释、没有"远程支持"这个问题
- **换来的新问题**：「为什么一个人做？」「有用户吗？」「收入怎么来的？」
- **这些问题的答案你能给**：产品定位、架构选型、审计清单、下一步路线

### 两条路的共同红线

1. 不把"知道"说成"做过"
2. 不编在职经历
3. 不讲自己没参与的项目（Q5 就是因此翻车的）
4. **只打开自己写的代码**

## 6. 三道会暴露短板的题 —— 诚实答反而加分

### 6.1 沙箱（第 23 题）

❌ 错误答法：编一个"我们用 Docker 做了隔离"——你一追问就露。

✅ 正确答案：

> 「我的 Agent 不执行用户代码，只调业务 API，所以没有沙箱需求——工具都是受控的服务端函数，参数走 class-validator 校验，写操作还要服务端 token + OTP。
> 沙箱在两类场景才成为必需：一是 Agent 要执行 Python/Shell，二是 AI Coding 工具要改代码。那时候需要文件系统隔离、网络出站限制、非 root、资源配额和命令白名单。Docker 只是弱隔离，不能等同于安全沙箱。」

**加分点**：你没有的东西，你能说清楚"什么时候才需要"——这是判断力。

### 6.2 上下文压缩（第 29 题）

❌ 错误答法：背"最近 N 轮 + 摘要 + 长期记忆"三段论，但你代码里没有。

✅ 正确答案：

> 「我现在是**截断**：`messages.slice(-20)`，保留最近 20 条原始消息。这是我要补的地方。
> 纯截断的问题是会把关键业务事实删掉——比如用户第三轮说的订单号。正确做法是三层：最近几轮保留原文，早期历史走摘要节点，需要长期保留的写独立存储。
> 摘要要有校验：用户目标、已确认事实、关键数字、待办事项不能丢。工具返回的冗长结果也要裁剪，只留状态码和关键字段。」

**证据**：`graph/constants.ts:16` `MAX_CONTEXT_MESSAGES = 20`，`agent-factory.ts:126` 的 `.slice(-MAX_CONTEXT_MESSAGES)`。

**加分点**：能指着代码说"这里现在是截断，差在哪"——比背标准答案强十倍。

### 6.3 反思 + 工具重试（第 32 题）

⚠️ 你有一半：**重试有，反思没有。**

✅ 正确答案（先说有的，再说没有的）：

> 「工具重试我已经做了：Agent Loop 里 `MAX_ITERATIONS = 3` 是硬上限；工具失败不抛异常，返回带 `error` 字段的结构化结果，模型能感知失败并给兜底回复，而不是整个请求崩掉。
> 反思节点我还没做，这是设计上要补的。如果加，我会用 StateGraph 拆成独立节点，而不是全塞进一个大 prompt：`tool_result_check` 判断工具是否成功 → 失败进 `retry_policy`（区分可重试的错误如超时/限流，和不可重试的如参数错误/权限拒绝）→ 成功进 `reflection` 检查证据是否充分 → 不通过回 agent 但要有 `reflection_count` 上限。
> 关键是重试和反思必须分开计数，否则会无限自循环。」

**加分点**：区分"执行异常重试"和"结果质量反思"——这是这题的核心考点，很多人答混。

## 7. 反问环节（第 36 题）

这份记录的候选人没有记录自己问了什么，但这是必答题。三个可用问题：

1. 「这个 Agent 现在有评测集吗？准确率是怎么衡量的？」——显示你重视度量
2. 「线上出问题时，怎么定位是检索错了还是生成错了？」——显示你有排障思路
3. 「这个岗位的 Agent，是新建还是接手已有系统？」——显示你关心落地条件

不要问：薪资、加班、能不能远程（这些留到 HR 面）。
