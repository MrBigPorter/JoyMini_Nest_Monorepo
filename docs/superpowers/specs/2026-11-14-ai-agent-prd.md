# AI Agent PRD

> 日期：2026-11-14
> 范围：`apps/api/src/client/ai-customer/`
> 定位：把 AI 客服从「能对话」推到「可信、可控、可评」
> 关联：`2026-11-14-enterprise-readiness-design.md`

---

## 1. 目标

系统已经能完成一次完整对话：识别意图、召回知识、调用工具、流式回复、必要时转人工。

但它目前的三个前提是**不可验证的**：

```
前提一：意图分类是准的        → 只有 63 题、68.2%，置信区间 ±11.5pp
前提二：AI 的回答解决了问题    → 只测了意图，没测任务是否完成
前提三：模型会老实调用工具     → 模型的参数可以指定任意身份
```

本 PRD 要求：把这三个前提变成可度量、可约束、可回归的工程事实。

## 2. 用户与场景

| 用户 | 场景 | 关心什么 |
|---|---|---|
| 终端用户 | 问订单、退款、余额 | 答得对、答得快、别乱动我的钱 |
| 客服人员 | 接管 AI 处理不了的会话 | 有上下文、不重复问 |
| 运营 | 改例句、改 prompt | 改完能验证有没有变好 |

## 3. 功能需求

### F1 意图路由可解释

- 每一次分类必须能回答：两路召回的原始分是多少、融合后多少、在哪一层被淘汰、为什么。
- 门禁必须作用在**融合之后**，不得让单路分数独立决定淘汰。
- 阈值只有一个事实来源。

**验收**：给定一个 traceId，能还原一次分类经过的每一层。

### F2 知识召回质量

- 多层召回结果合并后必须用统一尺度重排，不得直接比较不同量纲的分数。
- 召回失败或多层全空时，必须明确降级为「无知识可用」而不是静默返回空。
- 引用来源必须可追溯（哪篇文档、哪个 chunk）。

**验收**：一次回答能列出命中的知识来源；无命中时回答明确说明依据不足。

### F3 工具调用的身份不可伪造

- 工具参数中不得包含用户身份字段。
- 用户身份由调用链在构造工具时注入，模型无法覆盖。
- 工具必须声明**能力标记**（只读 / 写 / 需校验归属），执行前校验。**不引入 RBAC**——客户端用户没有角色体系。

**验收**：构造「以他人身份查询」的对话，参数中不出现身份字段，返回数据属于当前用户；未走确认流程直接调用写工具被拒。

### F4 写操作三重闸门

- 模型不得直接执行有副作用的工具。
- 写操作必须经过：执行前截停 → 一次性凭证 → 高风险操作二次验证。
- 参数必须经过白名单校验，剔除模型夹带的额外字段。
- 凭证必须与用户绑定、有短 TTL、只能消费一次。

**验收**：重放同一凭证被拒；夹带额外字段被拒；他人凭证被拒。

### F5 降级阶梯

- 模型超时、报错、不可用时，必须有明确降级路径，不得让用户「什么都收不到」。
- 降级内容必须是静态的（不依赖已故障的模型生成）。
- 降级原因必须可区分（低分 / 依赖故障 / 无候选）。

**验收**：故障注入后，用户收到固定话术，会话进入人工队列，日志记录原因。

### F6 任务成功率可度量

- 在意图准确率之外，必须有「问题是否被解决」的判定。
- 判定由与被测模型**不同厂商**的模型完成（新增一个便宜 API，仅周级调用），并有人工抽检校准。
- 评测用固定 fixture 用户；写工具不真实执行，只判定确认卡片是否正确生成。
- 报告需同时给出两个指标与各自的不确定度。

**验收**：报告中意图准确率与任务成功率并列；人工抽检一致率 ≥80%。

### F7 线上反馈回流

- **显式标注**：客服在 admin 会话页对 AI 回复标注「正确 / 有误 + 错误类型」。
- **隐式信号**：用户转人工、重复追问、中途放弃，自动记为弱反馈。
- 两类信号都进入待标注列表，可导出为评测集样本。
- 评测集必须定期从这些信号中补充。

**验收**：一次点踩 → 落库 → 出现在 badcase 导出中 → 可被加入回放集。

### F8 上下文可控

- 多轮对话的上下文不得无限增长。
- 超出预算时按明确策略压缩（摘要或裁剪），不得静默丢弃关键状态。
- 单轮对话必须有全局时间上限与取消能力。

**验收**：构造 30 轮对话，上下文长度有上界；用户断连后模型调用在 5 秒内停止。

## 4. 非功能需求

| 编号 | 要求 |
|---|---|
| N1 | 回答不得直接暴露内部工具返回的原始结构 |
| N2 | 日志与链路记录中不得出现用户原文 |
| N3 | 单轮对话的模型调用次数有预算上限 |
| N4 | 新增评测能力不得改变线上分类路径的行为 |

## 5. 现有能力盘点

已具备：

- 双路召回（pgvector + 关键词）与加权融合
- 四层 RAG + reranker
- 工具注册表、写操作截停、一次性凭证、OTP 二次验证
- 转人工状态机与认领 CAS
- 结构化日志按 traceId 串联
- 63 题 golden set 回放工具

## 6. 已知缺陷（本 PRD 要求修复或明确记录）

| 缺陷 | 处理方式 |
|---|---|
| 门禁在融合之前 | 本 PRD 内修复 |
| 关键词检索层 SQL 参数错位 | 本 PRD 内修复 |
| 工具参数含身份字段 | 本 PRD 内修复 |
| 依赖排序非拓扑、方向矛盾 | 本 PRD 内修复或明确降级为「仅支持两层」 |
| 转人工后 in-flight AI 不取消 | 记入 F8，本 PRD 内修复 |

## 7. 不做

- 增加或删除意图标签（仍为 9 个）
- 更换基座模型
- 语音、多模态接入
- 自主规划（让模型自己拆解任务）

## 8. 验收总表

- [ ] 一次分类可按 traceId 还原全部关卡
- [ ] 门禁只在融合后生效
- [ ] 回答可列出知识来源
- [ ] 工具参数中无身份字段，越权被拒
- [ ] 写操作三闸门全部有效
- [ ] 故障注入能正确降级并转人工
- [ ] 报告含意图准确率 + 任务成功率 + 不确定度
- [ ] 差评可回流到评测集
- [ ] 30 轮对话上下文有上界
- [ ] 断连 5 秒内停止推理
