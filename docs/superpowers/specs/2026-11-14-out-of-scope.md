## 为什么要有这份文档

一份只列"要做什么"的方案，会让人误以为作者不知道其余部分。这份文档存在的意义是：**证明判断是主动的，不是遗漏**。

每条都回答三个问题：是什么、为什么不做、什么时候做。

---

## 一、本次明确不做（11 条）

### 可靠性

**P1-8 聊天 DTO 无长度上限**
- 为什么不：属输入校验，风险是数据库膨胀与提示词超长；当前有 SSE 限流兜底，优先级低于成本护栏。
- 何时做：出现单条超长消息导致模型报错时。

**P1-9 健康检查只证明进程活着**
- 为什么不：当前单实例部署，健康检查失败即整机不可用，误判概率低。
- 何时做：迁到多实例或滚动发布之前（届时必须拆 liveness / readiness）。

**P1-10 容器以 root 运行**
- 为什么不：单机自运维环境，收益低于改造成本与回归风险。
- 何时做：对外开放或过安全审计前。

**P1-14 `lastMsgSeqId` 与消息创建非同一事务**
- 为什么不：影响是序号空洞，不影响正确性；消息已有主键唯一兜底。
- 何时做：与 P1-11 的唯一索引一起做更划算。

### 安全与合规

**P1-12 提现无 KYC / 日限额 / 黑名单**
- 为什么不：属业务风控策略，需要产品定规则，不是工程缺口。
- 何时做：有真实资金流与合规要求时。

**P1-13 兑换码无尝试次数限制**
- 为什么不：可通过限流层临时缓解；彻底解决需要业务定义锁定策略。
- 何时做：上线兑换码营销活动前。

**P1-15 管理端敏感操作无独立审计日志**
- 为什么不：已记录操作人，缺的是独立审计流；影响是追溯困难，不是即时风险。
- 何时做：多名管理员协作或需要对外审计时。

**P2-7 无数据留存 / PII 脱敏 / 删除策略**
- 为什么不：涉及合规决策（留存多久、哪些字段算 PII），需产品与法务输入。
- 何时做：面向真实用户开放前，无法回避。

### 工程与运维

**P1-16 CI 排除 api lint、无安全扫描**
- 为什么不：属流程改进，不改代码正确性；当前靠类型检查与单测把关。
- 何时做：团队协作或开源时。

**P2-6 无 SLO / 告警通道**
- 为什么不：指标化（阶段一 F5）是前置条件，先有数再有告警。
- 何时做：阶段一完成后紧接着做。

**P2-9 无 IaC / 环境一致性校验**
- 为什么不：单机部署，环境漂移靠文档约束；引入 IaC 的成本高于收益。
- 何时做：多环境或多实例时。

## 四、这份文档怎么用

- **对内**：任何"要不要顺便修一下"的讨论，先查这张表。表里有的，说明已经想过；表里没有的，才需要重新评估。
- **对外**：被问到某个缺口时，答案不是"没考虑到"，而是"考虑过，优先级排在这里，原因是……"。
- **定期更新**：每完成一项从这里移到完成清单，新增的缺口同步写入。
