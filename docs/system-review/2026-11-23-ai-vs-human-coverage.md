# AI 与人工边界 — 需要人工的场景清单

> 2026-11-23。依据当前 AI 工具清单（35 个工具）、提现/券/地址的确认卡流程与后台审核流程整理。
> 目的：区分「用户手动」「客服人工」「后台审核」三类必须人工的场景；其余场景由自动化脚本验证。

## 1. 用户必须在 App/外部页面完成（AI 只能引导）

| 场景 | 为什么 AI 不能做 | 用户操作 | 验收点 |
|---|---|---|---|
| 充值/存款 | 没有 `recharge` 工具；需 Xendit 支付页 | App「我的 → 钱包 → 充值」选金额/渠道 → 支付 | 支付成功后余额增加 |
| KYC 提交 | AI 只有 `getKycDetail`/`getIdTypes`（只读） | App KYC 页上传证件/活体 | 状态变为审核中/已通过 |
| 支付/绑卡/支付密码 | 聊天禁止收集卡号/CVV/密码 | Xendit 页面或 App 支付设置 | 支付成功/绑定成功 |
| 手机号绑定/更换、密码、登录 | 没有对应写工具 | App 账号安全页 | 换绑/改密成功 |
| 订单取消/退款/退货 | 订单工具只读，没有 cancel/refund | App 订单页或人工客服 | 订单状态变化/退款到账 |
| 大额/风控提现审核 | AI 只提交申请；审核与结算在后台 | 等待财务审核 | 提现单状态流转、到账 |
| 账号注销/安全设置 | 需强身份验证 | App/人工 | 注销完成 |

## 2. 必须转人工 / 客服人工处理

| 场景 | 触发方式 | 人工动作 |
|---|---|---|
| 退款、退货、补偿、政策外例外 | 用户提出 / AI 无法处理 | 客服按售后政策处理 |
| 支付失败、充值未到账、重复扣款 | 用户反馈 | 财务对账、补单/退款 |
| KYC 驳回申诉、风控冻结/解冻 | 用户申诉 | 审核/风控复核 |
| 提现审核与结算 | AI 提交后 | 财务审核、`settleWithdrawal` |
| 投诉/强烈负面/明确要求人工 | 自动转人工（关键词/情绪/重复） | 客服认领并回复 |
| 账号被盗/异常登录 | 用户反馈 / 风控 | 安全处置 |
| 复杂售后（多订单、跨渠道） | AI 只能查 | 客服人工处理 |

## 3. 后台人工待办队列

- 待接入客服队列：认领（claim）、回复；SLA 超时回收
- `handoffCallback=pending` 的留言/回调
- 提现审核/结算
- KYC 审核
- 退款/售后工单
- AI Ops：低分评测、安全事件、异常 trace 处理

## 4. 系统自动转人工的触发条件

- 用户明确说「转人工」
- 强负面情绪（投诉/愤怒）
- 同一问题连续重复（`repeatCount`）
- AI 模型故障/超时（`degradeToHuman`）
- 聊天中索要银行卡/身份证/密码（拦截并转人工）
- 无客服在线 → 留言/回调（仍需人工后续跟进）

> 配额耗尽目前只提示「稍后再试/留言」，**不会自动转人工**——已知改进点。

## 5. 可自动化验证的场景

脚本：`scripts/ai-acceptance.mjs`（通过测试账号发真实消息，走完整 socket/HTTP/卡片链路）。

| # | 场景 | 断言 |
|---|---|---|
| 1 | 闲聊「你好」 | 有 AI 回复 |
| 2 | 「我的钱包余额是多少」 | 回复含 ₱ / 余额 |
| 3 | 「帮我查一下我的订单」 | 有 AI 回复；订单意图 |
| 4 | 「帮我看看优惠券」 | 只含未使用券；**不含已过期的 Big Spender** |
| 5 | 「看看可领取的优惠券」 | 含有效测试券；不含已过期券 |
| 6 | 「帮我领取 <测试券名>」 | 弹卡 → 确认 → EXECUTED；用户券 +1 |
| 7 | 「提现 100 到 GCash Withdraw…」 | 弹卡 → 确认 → OTP → EXECUTED；冻结余额 +100 |
| 8 | 「我要转人工」 | 会话进入 `awaiting_human` |

## 6. 运行方式

```bash
# 后端容器内执行（需要 JWT_SECRET / DATABASE_URL 等已在容器 env）
docker exec \
  -e TEST_USER_ID=<测试用户 id> \
  lucky-backend-dev \
  node /app/scripts/ai-acceptance.mjs
```

可选环境变量：

- `OTP_CODE`（默认 `OTP_DEV_CODE`，本地为 `123456`）
- `API_BASE`（默认 `http://localhost:3000/api/v1`）
- `SOCKET_URL`（默认 `http://localhost:3000`）
- `KEEP_DATA=1`：保留验收会话与测试券，便于排查

脚本会创建一条独立的 `【AI验收】` 会话和一个临时券，结束后清理；提现会在测试账号上真实产生一笔冻结（测试数据，无法自动撤销）。

## 7. 仍需人工执行的验收

- 卡片 UI 倒计时、OTP 输入态、支付 webview（Flutter 端）
- 充值/支付全链路（Xendit 页面）
- KYC 上传/审核
- 提现审核/结算
- 后台待接入队列、留言回调处理
