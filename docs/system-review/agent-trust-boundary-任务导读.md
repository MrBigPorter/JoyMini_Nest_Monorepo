# agent-trust-boundary 任务导读

> 给后端学习几个月的读者。每个任务三行：做什么 / 为什么 / 怎么验。
> 不懂的概念先看 §1 概念卡。

---

## 1. 概念卡（先看这个）

### 1.1 闭包注入
**生活类比**：餐厅服务员把**桌号**写在点菜单上带进厨房。厨师不需要问顾客"你几号桌"——单子上有。
**技术含义**：函数在创建时就把外部变量"记"下来了。`createTools(ctx)` 里的 `ctx.userId` 在工具被调用时自动可用，模型不需要（也不能）提供。

### 1.2 能力标记
**生活类比**：门禁卡上有颜色——红卡能进机房，蓝卡只能进办公区。保安看卡，不靠记忆。
**技术含义**：工具自己声明"我是只读的"或"我是写操作"，系统按声明决定要不要拦、要不要校验归属。

### 1.3 幂等
**生活类比**：电梯按钮。按一次和按三次，电梯都只来一趟。
**技术含义**：同一个操作执行多次，效果和执行一次相同。用"幂等键"识别"这是不是同一个操作"。

### 1.4 单飞（single-flight）
**生活类比**：银行只有一个窗口，取号后排队。不会让两个人同时办同一笔业务。
**技术含义**：同一时刻只允许一个任务处理同一个会话，第二个要么等待要么被拒。

### 1.5 唯一索引
**生活类比**：身份证号，全国不能有两个人同号。这是户籍系统层面保证的，不是靠人记。
**技术含义**：数据库层面对某几列做唯一约束，插入重复直接报错。

### 1.6 白名单
**生活类比**：机场安检只放行清单上的物品，清单外一律扣下。
**技术含义**：只允许预先列出的类型通过，其余默认拒绝。比"黑名单"安全，因为黑名单总有漏网。

### 1.7 结构化拒绝
**生活类比**：取款机不吐钱时会打印一张凭条说明原因，而不是直接死机。
**技术含义**：拒绝时返回一个规范的结果对象（含原因码），而不是抛异常。调用方可以据此继续处理。

### 1.8 线程键（thread key）
**生活类比**：病历号。同一个人的所有就诊记录都挂在这个号下面。
**技术含义**：标识"这次对话属于哪一段上下文"，用来存取会话状态。

## 2. 任务导读（28 项）

### 阶段 1：身份闭包注入（6 项，约 2 天）

| # | 做什么 | 为什么 | 怎么验 |
|---|---|---|---|
| 1.1 | 9 个工具工厂函数增加 `ctx: { userId }` 参数 | 让身份从调用链进来，而不是从模型进来 | `tsc` 报的错全部集中在这 9 个文件和调用点 |
| 1.2 | 删掉 schema 里的 `userId` 字段 | 模型看不到这个参数，就不可能伪造 | `grep -rn "userId: z.string()" graph/tools/` 无输出 |
| 1.3 | 工具内部改用 `ctx.userId` | 数据来源换掉 | 逐文件确认没有 `args.userId`，`tsc` 0 error |
| 1.4 | 构造工具的地方传入 `opts.userId` | 把身份递给工厂 | `tsc` 0 error，调用链无遗漏 |
| 1.5 | 补一条单测：模型给身份也不生效 | 防止以后有人改回去 | 用例通过；把 `ctx.userId` 改回 `args.userId` 时用例变红 |
| 1.6 | 跑全量单测 | 确认没改坏别处 | 除 2 个已知过期套件外全绿 |

> **红绿验证**：先让测试失败（红），再让它通过（绿）。这样能证明测试真的在测东西，而不是永远通过。

### 阶段 2：能力标记与确认流程（6 项，约 2 天）

| # | 做什么 | 为什么 | 怎么验 |
|---|---|---|---|
| 2.1 | 工具类型增加 `capability: { kind, requiresOwnership }` | 让工具声明自己的性质 | `tsc` 0 error |
| 2.2 | 给全部工具标上能力 | 没有标记就无法判断 | 遍历注册表，无 `undefined` |
| 2.3 | 确认流程改为读能力标记 | 手工名单会漏（P1-6 就是这么来的） | 删掉旧集合后 `tsc` 无引用，既有用例全绿 |
| 2.4 | 把 `createAddress` / `updateAddress` 纳入截停 | 它们现在能直接执行 | 两条用例断言"未确认不调 service" |
| 2.5 | 启动自检：写了但没纳入确认就告警 | 防再次遗漏 | 临时制造一个漏网工具，启动可见 error 日志 |
| 2.6 | 归属校验：目标不属于本人则拒绝 | 防越权读 | 构造他人数据参数，返回结构化拒绝并记录事件 |

## 3. 怎么学最有效

```
第 1 遍   只看 §1 概念卡，不碰任务      10 分钟
第 2 遍   用 §2 的表判断"哪个任务我完全看不懂"  5 分钟
第 3 遍   从那个任务开始，手把手做        一个任务 1-2 小时
```

**不要一次看 28 个。** 挑一个真正想懂的，做完一个再下一个。

推荐起点：**1.1 + 1.2**——它同时涉及"闭包"和"schema 校验"两个基础概念，做完你会对工具是怎么被模型调用的有完整认识。
