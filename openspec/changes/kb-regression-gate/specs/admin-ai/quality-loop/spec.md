# Spec Delta

## ADDED Requirements

### Requirement: 知识库回归状态必须可见

系统 SHALL 在管理端展示当前语料指纹、与上次全量的差异文档、受影响用例数与待激活文档，并区分「已覆盖」「有变更」「需先跑全量」三种状态；MUST NOT 只显示一个无法解释的分数。

#### Scenario: 有知识库变更

- **WHEN** 当前语料与上次全量不一致
- **THEN** 页面列出变更文档与受影响用例数，并提供可复制的子集执行入口

#### Scenario: 无变更

- **WHEN** 当前语料与上次全量一致
- **THEN** 页面显示「已覆盖」，受影响用例为 0

#### Scenario: 缺少全量基线

- **WHEN** 没有任何带用例快照的全量运行
- **THEN** 页面提示先执行一次全量，而不是显示空列表

### Requirement: 运行证据必须可从管理端查看

系统 SHALL 为评测运行提供证据查看入口，展示是否可用于发布及各校验项结果；不通过的项 MUST 附可读原因，不得只显示状态码。

#### Scenario: 证据通过

- **WHEN** 管理员查看一次合法全量运行的证据
- **THEN** 页面展示通过结论、运行标识、知识库指纹与服务端版本

#### Scenario: 证据不通过

- **WHEN** 运行是子集、语料不稳定或指纹与当前不一致
- **THEN** 页面逐项说明不通过原因，并提示下一步动作
