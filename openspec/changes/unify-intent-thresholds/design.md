# Design

## Context

现状的四层判定各自带着自己的数字，且顺序是「先卡门禁、后融合」：

| 层 | 位置 | 现取值 | 作用对象 |
|---|---|---|---|
| 向量召回及格线 | `intent-classifier.ts:124` | 0.70 | 单条例句的余弦相似度，**融合前** |
| 平局判定阈值 | `intent-classifier.ts:415` | 0.02 | 已融合的意图分，用于 catch-all 让位 |
| 路由回落线 | `intent-router.node.ts:39` | 0.50 | 分类器出口的 top-1，低于则整轮交大模型 |
| 执行门禁 + 边际 | `orchestrator.node.ts:314-315` | 0.70 / 0.05 | 已融合的意图分 |

两处非显然的耦合需要在设计阶段处理：

1. **BM25 单路命中的分数被人为压到 0.21–0.30**（`bm25Score × 0.3`），它通过了分类器的 0.70 检查，却过不了路由的 0.50，于是又被退给大模型重判。也就是说 BM25 单路命中的真实门槛是 0.50，不是 0.70——没有一处代码写明这件事。
2. **向量门禁在融合前**，一条 0.69 的向量命中在融合前就被丢弃；若同时有 BM25 命中，它只能走「单路打折」分支拿到 0.27，而按融合公式本应是 `0.7×0.69 + 0.3×0.90 = 0.753`。

规格见 `specs/ai-customer/intent-classification/spec.md` 与 `specs/ai-customer/intent-selection/spec.md`；动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 让「分数是否及格」这件事在代码里只出现一次判断、只有一个数值来源
- 让门禁的位置与它的语义一致：门禁针对的是**意图**，不是**某一路的证据**
- 让 BM25 单路命中的真实门槛变成显式常量，而不是两层阈值的偶然乘积

**Non-Goals:**

- 不调整任何阈值的数值本身（本次只改位置与来源）
- 不改向量模型、BM25 排序、召回条数、融合权重
- 不把阈值搬进数据库或配置中心
- 不改 `intent_examples` 表结构与后台管理界面

## Decisions

### D1. 常量以扁平具名导出，不用嵌套配置对象

新增 `graph/constants/intent.ts`，按语义扁平导出，每个常量自带单位与作用对象注释。

```ts
/** 向量/关键词单路召回的及格线（0–1 余弦相似度），作用于单条例句 */
export const RECALL_MIN_SIMILARITY = 0.7;
/** 融合后意图分的及格线，作用于按域去重后的意图 */
export const INTENT_MIN_SCORE = 0.7;
/** 两个意图分差小于此值时视为模糊，需保留竞争者 */
export const INTENT_SCORE_MARGIN = 0.05;
/** 两个意图分差小于此值时触发 catch-all 让位 */
export const INTENT_TIE_EPSILON = 0.02;
/** 分类结果弱于此值时整轮交大模型重判 */
export const ROUTER_FALLBACK_THRESHOLD = 0.5;
/** 向量路 / 关键词路的融合权重 */
export const VECTOR_FUSION_WEIGHT = 0.7;
export const BM25_FUSION_WEIGHT = 0.3;
```

**为什么不用嵌套对象**（`INTENT.THRESHOLDS.RECALL`）：嵌套会让调用点读起来是 `x >= INTENT.THRESHOLDS.RECALL`，评审时无法一眼看出比较的是哪个量，而这次的 bug 恰恰是「比较对象错了」。**为什么不进配置中心**：阈值变更必须配 golden set 回放才能合入，放进 DB 会让变更绕过代码评审，把行为差异藏进数据。

**为什么 `RECALL_MIN_SIMILARITY` 与 `INTENT_MIN_SCORE` 数值相同仍要分开**：它们作用对象不同（单条例句 vs 去重后的意图），且未来大概率会分道——合并成一个常量会让 D2 的顺序修正无从表达。

### D2. 门禁迁移到融合之后，且只判一次

新流程固定为五步，顺序不可调换：

```
1. 两路各自取域内最高分（不做阈值判断）
2. 加权融合：两路都有 → w1·v + w2·b；只有关键词 → b × w2
3. 按域去重（防御性保留）
4. 施加 INTENT_MIN_SCORE
5. 输出候选集，交由选择层判边际与让位
```

`human_support` 的 BM25 缺失惩罚仍在第 2 步之前作用于向量分（保持现有语义：惩罚的是「语义相似但没有关键词佐证」这件事）。

**为什么把去重放在融合与门禁之间**：融合是按域做的（`Map<domain, score>`），天然已经去重；第 3 步保留为显式防御，防止未来新增召回路时漏掉。数学上「先过滤后去重」与「先去重后过滤」在取最大值时等价——现有顺序**不是** bug，真正的 bug 是第 1 步之前就用了阈值。设计上一并写死，避免下次重构再猜。

**替代方案**：只在向量路上把阈值降到 0.0，把门禁完全交给第 4 步。否决——向量召回会把整张表的低分例句全拉进来，融合前的 `human_support` 惩罚与 BM25 单路分支都会失去意义。

### D3. 显式承认 BM25 单路命中的真实门槛

`BM25_FUSION_WEIGHT`（0.3）意味着关键词单路命中的上限就是 0.3，低于 `ROUTER_FALLBACK_THRESHOLD`（0.5）。这在现状下是**有意的**：只有关键词佐证、没有语义相似度的意图，确实该交大模型重判。设计上把它写成一条显式规则：

> 仅关键词命中的意图，融合后分数上限为 `BM25_FUSION_WEIGHT`，必然低于 `ROUTER_FALLBACK_THRESHOLD`，因此必然触发大模型重判。

代码注释与日志都按这句话写，不再让读者从两层阈值的乘积里倒推。

**替代方案**：给 BM25 单路命中加一个提升系数，让它有机会独立胜出。否决——本次目标是消除歧义，不是调整召回质量；要动召回质量得先有 A/B 数据。

### D4. 数值冻结，顺序变更单独可回滚

常量落地的提交**只做替换、不改数值**，此时行为应完全不变，可用现有单测证明。顺序修正单独一个提交，便于单独 revert。

### D5. 文档改为引用，不再重复数字

`CLAUDE.md` 的 Key Architecture 段、`docs/AI-joymini/63-Intent-Score-Gap-Check-Spec.md`、`docs/current-task.md` 的 T2-2 行，一律改成指向 `graph/constants/intent.ts`，不再写具体数值——这次三方不一致的根源就是同一数字抄了三份。

### D6. 顺序修正以回放对比作为合入门槛

`tools/eval/run-replay.sh` 在顺序修正前后的 Top-1、macro-F1 与各意图精确率必须给出对比表。若 `rag` 精确率无改善或总体 Top-1 下降超过 1 个百分点，则只保留 D1/D3/D5，回退 D2 的顺序变更。

## Risks / Trade-offs

- **[顺序修正会改变线上意图分布]** → D4 拆成独立提交 + D6 回放对比；不达标就只 revert 那一个提交，常量收敛仍然保留。
- **[门禁后移会让候选集变大]** → `INTENT_MIN_SCORE` 仍是 0.7，融合分不变的意图进出不变；只有「单路略低但融合过线」的新样本进入，数量应可忽略。回放时对比候选集大小确认。
- **[BM25 单路命中 0.21–0.30 的样本仍被大模型重判，成本不变]** → 这是有意的（D3），本次不优化；若后续要省 token，另开变更把该分支改为「直接判兜底」。
- **[常量被绕过]** → 评审时以 `specs/.../spec.md` 的「单一事实来源」要求为准；必要时补一条 lint 规则禁止在 `graph/**` 出现裸浮点阈值字面量。
- **[`docs/AI-joymini/63-*.md` 是历史档案，改它等于改档案]** → 按本仓库既定策略，历史文档不重写；这次的改法是在文件开头加一行「本文阈值已迁移至…，数值以代码为准」的横幅，正文不动。

## Migration Plan

1. 提交 A：新增常量模块 + 全量替换引用（行为不变）→ 全量单测应全绿
2. 提交 B：融合与门禁顺序修正（行为变更）→ 新增「融合分过线但向量分 0.69」用例，红绿验证
3. 提交 C：注释、文档、`CLAUDE.md` 对齐
4. 回放：`tools/eval/run-replay.sh` 出对比表，写入 `docs/AI-joymini/` 新编号文档
5. 回滚：提交 B 单独 revert 即可回到「常量已收敛 + 顺序未变」的中间态

## Open Questions

- 回放后若发现 `rag` 精确率仍低，是否需要在本次一并调整 `INTENT_MIN_SCORE` 的数值？—— 留待回放数据出来再定，不影响本设计的结构与任务拆分。
