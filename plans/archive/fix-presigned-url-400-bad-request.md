# Fix: Presigned URL PUT Returns 400 Bad Request

## Root Cause

The PUT to the Cloudflare R2 presigned URL returns **400 Bad Request** because the axios request interceptors in [`HttpClient`](apps/admin-blog/src/api/http.ts:91) add **extra headers** that are not part of the presigned URL signature.

### What happens:

1. [`HttpClient.setupInterceptors()`](apps/admin-blog/src/api/http.ts:93) adds `Authorization: Bearer {token}` (line 101) and `Accept-Language: {locale}` (line 107) to **every** axios request
2. When `uploadDirect()` calls [`this.instance.put(uploadUrl, file, ...)`](apps/admin-blog/src/api/http.ts:574), the interceptor adds these extra headers to the PUT request
3. The presigned URL was generated by [`getSignedUrl()`](apps/api/src/common/upload/upload.service.ts:200) which signs **only** the `Content-Type` header and the HTTP method
4. Cloudflare R2 validates the request against the signature — **extra headers mismatch** → **400 Bad Request**

### Why chat module works:

The chat frontend ([`ChatWindow.tsx`](apps/admin-next/src/components/customer-service/ChatWindow.tsx:133)) uses **native `fetch()`** for the PUT:

```js
await fetch(tokenResult.url, {
  method: 'PUT',
  headers: { 'Content-Type': file.type },
  body: file,
});
```

Native `fetch()` bypasses axios interceptors entirely, so no extra headers are sent.

## Fix Strategy

### Change 1: Modify `uploadDirect()` in [`http.ts`](apps/admin-blog/src/api/http.ts:559)

Replace the `this.instance.put()` call with a **native `XMLHttpRequest`** wrapped in a Promise. This:
- ✅ **Bypasses axios interceptors** (no extra headers)
- ✅ **Supports upload progress** via `xhr.upload.onprogress`
- ✅ **Matches the chat module's working pattern** (no axios for the PUT)
- ✅ **Works with Cloudflare R2 presigned URL signature validation**

**Before:**
```typescript
// Step 2: PUT file directly to R2
await this.instance.put(uploadUrl, file, {
  headers: { 'Content-Type': file.type },
  onUploadProgress: (e) => {
    if (onProgress && e.total) {
      const percent = Math.round((e.loaded * 100) / e.total);
      onProgress(percent);
    }
  },
});
```

**After:**
```typescript
// Step 2: PUT file directly to R2 using XMLHttpRequest
// - Native XHR avoids axios interceptors that add non-signed headers
// - Preserves upload progress tracking
await new Promise<void>((resolve, reject) => {
  const xhr = new XMLHttpRequest();
  xhr.open('PUT', uploadUrl);
  xhr.setRequestHeader('Content-Type', file.type);

  xhr.upload.onprogress = (e) => {
    if (onProgress && e.lengthComputable) {
      const percent = Math.round((e.loaded * 100) / e.total);
      onProgress(percent);
    }
  };

  xhr.onload = () => {
    if (xhr.status >= 200 && xhr.status < 300) {
      resolve();
    } else {
      reject(new Error(`Upload failed with status ${xhr.status}`));
    }
  };

  xhr.onerror = () => reject(new Error('Upload failed: network error'));
  xhr.send(file);
});
```

### No other changes needed

- Backend endpoints (`presigned-url`, `confirm`) are **working correctly**
- Frontend API wrappers (`uploadMediaDirect`) are **correct**
- `BlogArticleModal.tsx` and `RichTextEditor.tsx` call sites are **correct**
- Only the HTTP transport for the PUT step needs fixing
